# SRE Runbook: Incident Response & Escalation Protocol

**Runbook ID:** RB-OPS-01  
**Category:** Operational Incident Response  
**Target Systems:** Aegis Ingress Gateways, Control Plane, Redis, PostgreSQL, Audit Ingestion Worker  
**Standard Structure:** Standard 6-Part Operational Runbook (Pattern 11)  

---

## 1. Metadata, Severity Classification & Escalation Matrix

### Incident Classification Matrix
| Severity Level | Definition & Criteria | Target MTTR | SLO / Security Impact | Alert Triggers |
|---|---|---|---|---|
| **SEV-1 (Critical)** | Active security bypass, data corruption, total gateway ingress outage (HTTP 503 fleet-wide), or confirmed signing key leak. | **< 15 minutes** | Breaches 99.9% availability / Zero-Trust invariant violation. | `AegisGatewayFleetUnhealthy`, `AegisSecurityBypassDetected`, `AegisAllReplicasDown` |
| **SEV-2 (Major)** | Loss of redundancy (e.g. 2 of 3 replicas unhealthy), control plane gRPC partition (>30s), or spool saturation $>80\%$. | **< 30 minutes** | At risk of failing closed; elevated p99 latency. | `AegisSnapshotLeaseExpired`, `AegisWALSpoolWarning`, `AegisGatewayDegraded` |
| **SEV-3 (Minor)** | Async audit worker ingestion lag (>5m), background metric export scrape failure, or isolated replica restart. | **< 2 hours** | No user-facing impact; delayed PostgreSQL audit delivery. | `AegisAuditWorkerLag`, `AegisPrometheusScrapeFailed` |
| **SEV-4 (Advisory)** | Non-critical configuration drift, routine certificate renewal notification, or minor dashboard UI glitch. | **< 24 hours** | Zero operational impact. | `AegisCertExpiringSoon`, `AegisReplicaVersionDrift` |

## 2. Roles, Escalation Paths & Communications

### Command Structure
- **Incident Commander (IC):** Drives incident timeline, coordinates actions, owns executive/customer comms.
- **Technical Lead (TL):** Directs diagnostic commands, identifies root cause, approves remediation scripts.
- **Communications Lead (CL):** Publishes status updates to `#aegis-status` and customer status page.

### Communication Channels
- **Slack War Room:** `#incident-sev1-war-room`
- **PagerDuty Escalation Policy:** `Aegis-Gateway-OnCall` -> Secondary Lead -> Security Officer
- **Zoom / Meet Bridge:** Dedicated incident bridge auto-generated by PagerDuty incident trigger.

## 3. Rapid Containment Protocol

When a SEV-1 security incident or uncontrolled failure is identified, execute containment immediately:

1. **Traffic Shedding / Emergency Maintenance Mode:**
   ```bash
   # Route ingress traffic to emergency fallback or shed non-critical routes via HAProxy/Ingress
   kubectl scale deployment/aegis-ingress-lb --replicas=0 -n aegis-system
   ```
2. **Emergency Principal Quarantine (Hostile Actor Active):**
   ```bash
   # Immediately quarantine hostile identity across Redis
   curl -X POST http://control-plane:8084/control/v1/quarantine \
     -H "Content-Type: application/json" \
     -d '{"principal_id":"<compromised-id>","reason":"SEV1_CONTAINMENT","ttl_seconds":86400}'
   ```
3. **Verify Gateways Fail Closed:**
   ```bash
   # Confirm gateways return HTTP 503 instead of permitting unauthorized traffic
   curl -i http://gateway.aegis.local:8080/api/orders
   # Expected: HTTP 503 Service Unavailable (DEPENDENCY_OUTAGE_REDIS or LEASE_EXPIRED)
   ```

## 5. Diagnostic & Remediation Commands

### Check Cluster Health
```bash
# 1. Inspect Gateway Pods and Events
kubectl get pods -n aegis-system -o wide
kubectl describe statefulset/aegis-gateway -n aegis-system

# 2. Inspect Ingress Error Metrics
curl -s http://gateway-0:9091/metrics | grep "http_requests_total"

# 3. Check Live Logs for Security Invariant Halts
kubectl logs -n aegis-system -l app=aegis-gateway --tail=100 | grep -E "ERROR|HALT|fail_closed"
```

### Remediation Execution
```bash
# Roll restart degraded gateway replicas
kubectl rollout restart statefulset/aegis-gateway -n aegis-system
kubectl rollout status statefulset/aegis-gateway -n aegis-system --timeout=60s

# Verify readiness probes reactivate
kubectl get pods -n aegis-system -l app=aegis-gateway -w
```

## 6. Post-Incident Review (PIR) Template

All SEV-1 and SEV-2 incidents require a blameless Post-Incident Review meeting within 48 hours.

- **Incident Summary:** What happened, user impact, start and end times.
- **Root Cause Analysis (5 Whys):** Contributing factors, why fail-closed tripped.
- **Detection & Containment:** Time to detect (TTD), time to mitigate (TTM).
- **Corrective Actions:** Jira tickets created for hardening, unit tests, or runbook revisions.
