# Plan 05-01: Multi-Replica Gateway Cluster (3 Instances) Behind Load Balancer with Health Checking and 30s Graceful Drain

<threat_model>
### Plan 05-01 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 05-01 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Health and readiness probes (`/livez`, `/readyz`) abused to inject unauthenticated proxy requests or manipulate gateway state. | Probe endpoints are strictly scoped to static health paths (`/livez`, `/readyz`, `/healthz`, `/healthz/ready`) and only return static status text (`OK`, `READY`, or 503 error codes); any other route continues to the authenticated gateway pipeline. | Unit test in `internal/proxy/probe_test.go` verifying probe paths do not forward or proxy to backends. |
| **Tampering (T)** | Load balancer continues sending traffic to a degraded replica with expired snapshot lease (>60s) or saturated WAL spool (>90%). | The `/readyz` probe dynamically verifies `!isLeaseExpired(60*time.Second)`, `isSnapshotActive()`, and `!isSpoolSaturated()`. If any condition fails, it immediately returns `HTTP 503 Service Unavailable`, prompting HAProxy to evict the replica from the pool within 2 seconds. | Unit test in `internal/proxy/probe_test.go` validating `/readyz` returns 503 when lease is expired, uninitialized, or spool is saturated. |
| **Repudiation (R)** | Container termination (SIGTERM) abruptly severs in-flight client requests, discarding transaction state without audit completion. | Gateway implements two-phase shutdown: on SIGTERM, atomic draining flag flips immediately causing `/readyz` to return 503, while `http.Server.Shutdown(ctx)` waits up to 30 seconds for active in-flight requests to complete their proxy and audit WAL flush cycle. | Integration test in `cmd/gateway/main_test.go` validating in-flight requests finish during 30s drain while `/readyz` returns 503. |
| **Information Disclosure (I)** | HAProxy statistics or health check responses leak internal server architecture, private network IPs, or error details. | Health endpoints return minimal plaintext bodies (`OK\n`, `READY\n`); HAProxy stats listener is bound to dedicated port `:8404` and isolated from external ingress. | Verification of HAProxy configuration and curl output on probe endpoints. |
| **Denial of Service (D)** | Sudden container crash or planned rolling restart drops active connections causing transient 502 Bad Gateway spikes to clients. | HAProxy configured with `default-server inter 1s fall 2 rise 2` and Layer 7 HTTP health check (`option httpchk GET /readyz`); combined with 30s gateway drain, client traffic shifts seamlessly to surviving replicas without dropped requests. | Automated test asserting zero client connection drops during replica termination. |
| **Elevation of Privilege (E)** | Draining gateway replica fails open and bypasses token validation for remaining requests. | Draining status affects only the `/readyz` probe; all in-flight requests serviced during the 30s drain window pass through the full zero-trust pipeline (token validation, rate limit, OPA eval, WAL spool, mTLS assertion). | Unit tests verifying authorization enforcement is maintained throughout the drain window. |
</threat_model>

## Executive Summary

Plan 05-01 implements the first pillar of Phase 5: establishing a multi-replica gateway cluster operating behind a dedicated Layer 7 load balancer. In accordance with DIST-01 and Invariants 1 and 3, production zero-trust gateways must provide uninterrupted service during node failures and rolling updates.

This plan implements reusable `/livez` and `/readyz` health check probes in `internal/proxy/probe.go` that inspect snapshot freshness, lease validity, disk spool saturation, and draining state, making them importable across both the gateway daemon and test harnesses. It equips `cmd/gateway/main.go` with a two-phase 30-second graceful connection draining lifecycle on `SIGTERM`. It creates the HAProxy configuration (`deployments/compose/haproxy/haproxy.cfg`) and distributed Docker Compose profile (`deployments/compose/docker-compose.distributed.yml`) running 3 gateway replicas (`gateway-1`, `gateway-2`, `gateway-3`) with active health checks and stats observability, complete with Makefile management targets.

  - `(d *DrainingState) IsDraining() bool` returns boolean state.
- `internal/proxy/probe.go` exports `CreateProbeHandler(drainState *DrainingState, isLeaseExpired func(time.Duration) bool, isSnapshotActive func() bool, isSpoolSaturated func() bool, next http.Handler) http.Handler`:
  - `/livez` and alias `/healthz`: returns `HTTP 200 OK` with body `OK\n`.
  - `/readyz` and alias `/healthz/ready`:
    - If `drainState != nil && drainState.IsDraining()` is true: returns `HTTP 503 Service Unavailable` with body `DRAINING\n`.
    - If `isLeaseExpired != nil && isLeaseExpired(60 * time.Second)` is true: returns `HTTP 503 Service Unavailable` with body `LEASE_EXPIRED\n`.
    - If `isSnapshotActive != nil && !isSnapshotActive()` is true: returns `HTTP 503 Service Unavailable` with body `UNINITIALIZED\n`.
    - If `isSpoolSaturated != nil && isSpoolSaturated()` is true: returns `HTTP 503 Service Unavailable` with body `SPOOL_SATURATED\n`.
    - If all conditions pass: returns `HTTP 200 OK` with body `READY\n`.
  - All other routes pass through to `next` HTTP handler.
- `internal/proxy/probe_test.go` verifies:
  - `TestProbeHandler`: validates `/livez` 200, `/readyz` 200 when healthy, 503 when lease expired, 503 when uninitialized, 503 when spool saturated, 503 when draining, and passes non-probe paths to next handler.
- `go test -v -race ./internal/proxy/ -run TestProbeHandler` exits 0.
