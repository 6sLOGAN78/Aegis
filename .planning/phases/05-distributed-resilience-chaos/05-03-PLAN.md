# Plan 05-03: Chaos Fault Injection Suite and Reproducible k6 Performance Benchmark Suite

<threat_model>
### Plan 05-03 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 05-03 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Attacker exploits transient dependency outage (Redis or DB down) to replay revoked tokens or forge identity assertions. | Gateway enforces rigid 200ms timeout on Redis revocation checks failing closed with HTTP 503; assertion minting relies exclusively on local cryptographic keys, maintaining valid claims and request binding. | Chaos test `TestChaosSecurityInvariants` verifying invalid or revoked credentials fail under active outages. |
| **Tampering (T)** | Path traversal or header spoofing attempts succeed during high cluster load or node failover. | Path canonicalization (`ValidatePathZeroRepair`) and header stripping execute synchronously at ingress before proxying or state checks, rejecting invalid paths with HTTP 400 Bad Request regardless of cluster stress. | Chaos test `TestChaosSecurityInvariants` injecting malicious path traversal and spoofed headers during degraded states. |
| **Repudiation (R)** | Database outage causes gateway to silently drop audit records or disable durable audit spooling. | Gateway appends pre-forward decision records to local append-only WAL on disk with forced `fsync` before upstream dispatch; PostgreSQL outage only affects background batch drainage, never hot-path durability. | Chaos subtest in `TestChaosDependencies` verifying local WAL append during total database outage. |
| **Information Disclosure (I)** | Chaos tests or benchmark reports leak sensitive test tokens, private keys, or internal system topology. | Test fixtures generate ephemeral in-memory Ed25519 keys; benchmark scripts utilize demo user tokens without exposing credentials in logs. | Test audit asserting zero persistent credential leaks. |
| **Denial of Service (D)** | High traffic load (1,000 req/s) exhausts memory or CPU, causing gateway latency to breach the 20ms p99 SLA. | Precompiled OPA queries evaluate in-memory in <0.2ms; lock-free `sync/atomic.Pointer` eliminates mutex contention on hot path; connection pools reuse TCP connections. | k6 benchmark and Go microbenchmarks asserting `<20ms p99` latency under 1,000 req/s sustained load. |
| **Elevation of Privilege (E)** | Saturated WAL spool (90% capacity) causes gateway to bypass audit logging and permit requests without recording. | Saturated spool triggers circuit breaker: gateway halts permitted admissions with HTTP 503 (`SPOOL_SATURATED`), preserving fail-closed zero-trust semantics. | Chaos subtest in `TestChaosDependencies` verifying HTTP 503 response. |
</threat_model>

## Executive Summary

Plan 05-03 delivers the final validation and performance evidence for Phase 5. In accordance with DIST-01, DIST-03, and Invariants 1, 3, and 10, Aegis must demonstrate that its distributed architecture adheres 100% to fail-closed security semantics under severe infrastructure degradation, while satisfying low-latency performance SLOs under heavy load.

This plan constructs an automated Chaos Fault Injection harness in Go (`tests/chaos/chaos_test.go` and `tests/chaos/test_helpers.go`) that simulates killed gateway processes, severed Control Plane streams, 60-second lease expiration boundaries, Redis network partitions, PostgreSQL outages, and WAL spool saturation, proving zero fail-open bypasses across all failure modes. Furthermore, it creates a reproducible benchmark suite featuring Go microbenchmarks (`benchmarks/engine_bench_test.go`) and declarative Grafana k6 scripts (`benchmarks/k6/`) verifying that policy evaluation takes <0.2ms p50 / <2ms p99 and gateway added latency remains <20ms p99 under a sustained load of 1,000 requests per second.

## Must Haves

### Truths
- Killing a gateway replica during active traffic does not drop client connections or produce 500 errors through the load balancer.
- All failure modes (Redis partition, DB down, lease expiry >60s, spool saturation) adhere strictly to fail-closed semantics (503 response) with zero fail-open bypass.
- Negative security attacks (header spoofing, path traversal, untrusted certs) are 100% blocked under chaos conditions.
- In-memory OPA evaluation executes in <0.2ms p50 and <2ms p99.
- Added gateway proxy latency remains <20ms p99 under a sustained load of 1,000 req/s.
