# Plan 05-02: gRPC Reconnect Backoff with Randomized Jitter and Fleet Snapshot Convergence Tracking

<threat_model>
### Plan 05-02 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 05-02 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Unauthorized entity injects rogue snapshot acknowledgment pretending to be gateway replica. | Gateway messages over gRPC are bound to authenticated stream sessions; acknowledgments report gateway ID and Ed25519 signed snapshot versions verified by `AckTracker`. | Integration tests in `tests/chaos/convergence_test.go` verifying acknowledgment traceability. |
| **Tampering (T)** | In-flight request experiences inconsistent policy evaluation while snapshot is being activated across replicas. | Snapshot activations use lock-free atomic pointer swaps (`sync/atomic.Pointer[ActiveSnapshotState]`); each request evaluates atomically against either version $N$ or $N+1$, never an uncompiled or partial intermediate state. | Race-detector enabled tests running concurrent traffic during live snapshot broadcasts. |
| **Repudiation (R)** | Gateway replica silently lags on stale snapshot without control plane awareness. | `AckTracker` logs and records `active_version` and timestamp for each connected replica; `/control/v1/gateways` marks replicas lagging behind active snapshot as `degraded`. | Verification of convergence status reporting during integration tests. |
| **Information Disclosure (I)** | Reconnect backoff logs leak sensitive connection tokens or private control plane addresses. | Jitter and connection error logs record only sanitized endpoints and error strings, avoiding sensitive credentials. | Code inspection and log output assertions. |
| **Denial of Service (D)** | Control plane restart causes all connected gateways to reconnect simultaneously (thundering herd), crashing the control plane. | `StreamClient` enforces exponential backoff with Full Jitter: $T = \text{base} + \text{rand} \times (\min(\text{max}, \text{base} \times 1.5^n) - \text{base})$, spreading reconnect attempts uniformly across $[100\text{ms}, 5\text{s}]$. | Unit tests in `internal/snapshot/client_test.go` verifying statistical variance across 1,000 backoff calculations. |
| **Elevation of Privilege (E)** | Gateway disconnected from control plane authorizes requests using expired snapshot indefinitely. | Signed 10-second freshness leases must be renewed continuously; if disconnected for $>60$ seconds, gateway fails closed with `HTTP 503 Service Unavailable` (`POLICY_LEASE_EXPIRED`). | Lease expiry tests asserting 503 response after 60-second cutoff. |
</threat_model>

## Executive Summary

Plan 05-02 implements the distributed coordination and resilience mechanics required by DIST-01 and Invariants 4 and 5. In a distributed multi-replica topology, gateways must maintain resilient connections to the central Control Plane without inducing thundering herd failures upon control plane restart, and must converge to newly published policy snapshots rapidly and consistently.

This plan hardens `StreamClient` in `internal/snapshot/client.go` with a mathematically verified Full Jitter exponential backoff algorithm, providing unit tests that statistically validate uniform spread between 100ms and 5 seconds. It creates the foundational multi-replica test cluster harness in `tests/chaos/test_helpers.go` and a dedicated fleet convergence integration test (`tests/chaos/convergence_test.go`) running 3 concurrent gateway replicas under active traffic, verifying that all replicas receive, activate, and acknowledge new snapshot versions within 5 seconds at p99 with zero dropped requests.

<acceptance_criteria>
- `internal/snapshot/client.go` exports `CalculateFullJitterBackoff(attempt int, baseBackoff, maxBackoff time.Duration) time.Duration`:
  - Enforces base backoff `100ms`, maximum backoff `5s`, exponential factor `1.5`.
  - Calculates upper ceiling: `temp = min(maxBackoff, baseBackoff * (1.5 ^ attempt))`.
  - Generates uniform random sleep duration in range `[baseBackoff, temp]`.
  - Never returns a duration less than `baseBackoff` or greater than `maxBackoff`.
- `StreamClient.Start` integrates `CalculateFullJitterBackoff`:
  - Tracks consecutive failure attempts.
  - Resets attempt counter to 0 upon successful stream connection and first message receipt.
  - Sleeps for calculated jitter duration between reconnect attempts, respecting context cancellation and `stopCh`.
- `internal/snapshot/client_test.go` verifies:
  - `TestStreamClientJitterBackoff_Bounds`: asserts that backoff is always within `[100ms, 5s]` across 1,000 iterations for attempts 0 to 20.
  - `TestStreamClientJitterBackoff_Distribution`: asserts that for attempt 5, multiple samples exhibit non-zero variance (standard deviation $> 50$ms) demonstrating true randomization rather than deterministic sleep.
  - `TestStreamClient_StopIdempotent`: asserts that calling `Stop()` multiple times does not panic or deadlock.
- `go test -v -race ./internal/snapshot/ -run "TestStreamClientJitterBackoff|TestStreamClient_StopIdempotent"` exits 0.
</acceptance_criteria>
