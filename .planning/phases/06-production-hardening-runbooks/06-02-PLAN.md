# Plan 06-02: Security Audit Review, Negative Fuzzing Verification, and Credential Rotation Drill Runbooks

<threat_model>
### Plan 06-02 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 06-02 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Attacker uses a retired or revoked JWT signing key or compromised snapshot Ed25519 key to forge authentication tokens. | Dual-key verification windows enforce bounded overlap periods: once the overlap window elapses, the old public key is retired from the gateway keyset (`SetPublicKeys`), immediately causing all tokens signed by the old key to fail verification. | Automated drill in `tests/rotation/rotation_test.go` asserting tokens signed with retired keys return authorization error. |
| **Tampering (T)** | Unauthenticated or man-in-the-middle attacker injects forged policy snapshots or fake freshness leases during control plane key rotation. | Snapshot `Verifier` checks both snapshot envelopes and 10s freshness leases against a multi-key Ed25519 keyset. If neither the primary nor the newly added trusted public key validates the signature, the snapshot is rejected with `ErrInvalidSignature`. | Unit test in `internal/snapshot/verifier_test.go` and drill in `tests/rotation/rotation_test.go` asserting forged signatures are rejected. |
| **Repudiation (R)** | Key rotation actions executed without audit trail, obscuring who rotated keys and when active signing transitioned. | Control plane rotation steps require authenticated management API operations with operator identity logging, and gateway startup/reload logs record keyset fingerprinted updates without logging private key material. | Documentation checklist in `docs/audit/security-audit-report.md` and audit logging assertions. |
| **Information Disclosure (I)** | Rotating cryptographic keys leaks raw private keys in logs, metrics, or gRPC telemetry streams. | Rotation runbook commands and Go cryptographic structures keep private key material isolated to the signing entity; only public keys (`crypto.PublicKey`, `ed25519.PublicKey`) and x509 certificates are distributed to gateway verifiers. | Runbook review in `docs/runbooks/credential-rotation.md` and automated tests asserting only public keys are loaded into `TokenValidator` and `Verifier`. |
| **Denial of Service (D)** | Sudden replacement of signing key without overlap window immediately invalidates unexpired in-flight user tokens and gRPC streams, causing massive 401/403/503 outages. | Dual-key verification window architecture allows `TokenValidator` and `Verifier` to hold $\{K_{\text{old}}, K_{\text{new}}\}$, allowing existing in-flight tokens to complete their TTL while new tokens authenticate with $K_{\text{new}}$. | Automated concurrent load drill in `tests/rotation/rotation_test.go` proving 100% 200 OK continuity and zero 401 drops during key transition. |
| **Elevation of Privilege (E)** | Algorithmic confusion during key rotation (e.g. switching between Ed25519 and RSA or exploiting `alg: none`). | `TokenValidator` strictly maintains its pinned algorithm allowlist (`EdDSA`, `RS256`, `ES256`) and evaluates tokens against expected algorithms before attempting signature verification; `alg: none` is unconditionally rejected with `ErrInvalidAlgorithm`. | Negative unit test in `internal/identity/jwt_test.go` asserting `alg: none` rejection regardless of keyset state. |
</threat_model>

## Executive Summary

Plan 06-02 addresses the operational and cryptographic security requirements of the Aegis production deployment (AUTH-01, CTRL-02, PKI-01, GW-01). In zero-trust architectures, security credentials must be rotated on regular intervals (or immediately upon suspected compromise) without incurring client-facing downtime or dropped transactions.

This plan expands `internal/identity/jwt.go` (`TokenValidator`) and `internal/snapshot/verifier.go` (`Verifier`) to support thread-safe multi-key trusted keysets with dynamic addition and atomic retirement. It creates an automated integration drill suite in `tests/rotation/rotation_test.go` proving zero-downtime key rotation across three critical systems: User Bearer JWTs, Control Plane Ed25519 snapshot signing keys, and Workload mTLS Intermediate CAs. Finally, it delivers a formal Security Audit Report (`docs/audit/security-audit-report.md`) verifying all 12 security invariants and OWASP ASVS Level 1 controls, alongside an authoritative SRE Credential Rotation Runbook (`docs/runbooks/credential-rotation.md`).
