# Plan 02-01: Local PKI Generation and Dedicated Workload mTLS Listener (:9443) with SPIFFE URI SAN Parsing

<threat_model>
### Plan 02-01 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 02-01 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Unauthenticated external caller connects to workload listener without a client certificate, or presents a certificate signed by an untrusted CA. | Workload listener binds to dedicated port `:9443` configuring `tls.RequireAndVerifyClientCert` with the internal Aegis Root CA pool; Go stdlib TLS terminates the handshake before application processing (AUTH-02, Invariant 4). | Automated test in `tests/security/workload_identity_test.go` verifying handshake termination when client certificate is absent or signed by rogue CA. |
| **Spoofing (S)** | Workload client attempts to spoof identity via Common Name (CN), `X-Client-Cert-SAN`, or `X-Forwarded-Client-Cert` headers. | Workload identity is extracted strictly and exclusively from `r.TLS.PeerCertificates[0].URIs`. Common Name is ignored; all ingress headers are ignored (AUTH-02, Invariant 2). | Table-driven tests in `internal/identity/spiffe_test.go` asserting identity matches `spiffe://` URI SAN and rejects CN-only certificates. |
| **Tampering (T)** | Client presents a client certificate containing a non-SPIFFE URI scheme, a malformed path, or an untrusted trust domain (e.g., `spiffe://evil.com/workload/orders`). | `ExtractSPIFFEID` verifies URI scheme is `spiffe`, validates trust domain matches configured domain (`aegis.local`), and asserts valid path structure (`/workload/{service}` or `/ns/.../sa/...`). Returns typed errors (`ErrInvalidTrustDomain`, `ErrMalformedSPIFFEURI`). | Unit tests in `internal/identity/spiffe_test.go` testing untrusted trust domains and malformed URI paths. |
| **Repudiation (R)** | Workload requests or handshake rejections on `:9443` proceed without traceable request correlation. | Workload listener assigns cryptographically random UUID v4 `X-Request-ID` at socket arrival and formats RFC 7807 problem details containing correlation instance references. | Unit and security tests asserting `X-Request-ID` presence on all response paths. |
| **Information Disclosure (I)** | Workload listener TLS errors or certificate validation errors leak internal server file paths or sensitive runtime parameters. | Error responses return standardized RFC 7807 problem details with sanitized error descriptions (`application/problem+json`). | Test asserting RFC 7807 problem details structure on rejected credentials. |
| **Denial of Service (D)** | Volumetric TLS connection floods on port `:9443` exhaust gateway memory or goroutines before identity resolution. | Workload listener shares `ConcurrencyLimiter` bounding in-flight connections/requests; enforces `ReadHeaderTimeout = 5s`, `MaxHeaderBytes = 16 KiB`, and body limit `1 MiB`. | Concurrency limit tests in `internal/proxy/limiter_test.go` and dual server test suite. |
| **Elevation of Privilege (E)** | Confused Deputy: Client connects to workload listener `:9443` with a valid workload certificate, but injects an `Authorization: Bearer <user-jwt>` header to impersonate a privileged human user. | Workload listener ingress guard inspects incoming `Authorization` header. If present, it immediately rejects the request with HTTP 401 Unauthorized (`AMBIGUOUS_CREDENTIALS`), preventing ambiguous principal selection (AUTH-03, ADR-0003). | Negative security test in `tests/security/workload_identity_test.go` presenting both valid workload cert and Bearer JWT on `:9443`. |
</threat_model>

## Executive Summary

Plan 02-01 implements the first wave of Phase 2 by establishing cryptographic workload identity and ingress listener isolation. In accordance with ADR-0003 and NIST SP 800-207, human user traffic and automated machine workload traffic are separated into distinct physical network listeners: User Ingress (`:8080` HTTP / `:8443` TLS) and Workload Ingress (`:9443` mTLS).

To eliminate external CLI dependencies during testing and local execution, Plan 02-01 introduces a pure Go development PKI generator (`internal/pki`) capable of issuing Root CAs, workload client certificates with SPIFFE URI SANs (`spiffe://aegis.local/...`), and server certificates in under 5 milliseconds. The plan delivers strict SPIFFE identity extraction from verified peer TLS certificates (`internal/identity/spiffe.go`), extends runtime configuration with workload port and certificate path parameters (`internal/config`), equips the gateway with a dual-listener server manager (`internal/proxy/server.go`), and enforces strict rejection of Bearer tokens on the workload port to eliminate Confused Deputy vulnerabilities (AUTH-03).

<acceptance_criteria>
- `internal/identity/spiffe.go` defines sentinel errors:
  - `ErrNoPeerCertificate = errors.New("no peer certificate presented")`
  - `ErrMissingSPIFFEID = errors.New("certificate does not contain a SPIFFE URI SAN")`
  - `ErrInvalidTrustDomain = errors.New("certificate SPIFFE trust domain mismatch")`
  - `ErrMalformedSPIFFEURI = errors.New("malformed SPIFFE URI structure")`
- Exports `ExtractSPIFFEID(peerCert *x509.Certificate, expectedTrustDomain string) (string, error)`.
- Rejects `peerCert == nil` with `ErrNoPeerCertificate`.
- Iterates over `peerCert.URIs` ignoring non-spiffe schemes.
- Validates scheme is `spiffe` (case-insensitive).
- If `expectedTrustDomain != ""`, validates `uri.Host` matches `expectedTrustDomain` (case-insensitive); returns error wrapping `ErrInvalidTrustDomain` on mismatch.
- Asserts `uri.Path != ""` and `uri.Path != "/"`; returns `ErrMalformedSPIFFEURI` on empty or root paths.
- Returns full SPIFFE URI string (e.g. `spiffe://aegis.local/workload/orders`).
- If no valid SPIFFE URI is found across all URIs, returns `ErrMissingSPIFFEID`.
- Common Name (`peerCert.Subject.CommonName`) is ignored completely.
- Unit tests in `internal/identity/spiffe_test.go` cover valid SPIFFE URIs, gateway SPIFFE URIs, missing peer certs, empty URIs slice, non-spiffe schemes (`https://...`), untrusted trust domains (`spiffe://evil.com/...`), and empty path URIs.
- Unit test command exits with code 0:
  `go test -v -race ./internal/identity/ -run TestSPIFFE`
</acceptance_criteria>

<action>
1. Create `internal/identity/spiffe.go`:
   - Declare package `identity`.
   - Define sentinel errors: `ErrNoPeerCertificate`, `ErrMissingSPIFFEID`, `ErrInvalidTrustDomain`, `ErrMalformedSPIFFEURI`.
   - Implement `ExtractSPIFFEID(peerCert *x509.Certificate, expectedTrustDomain string) (string, error)`:
     - Check `peerCert == nil`: return `"", ErrNoPeerCertificate`.
     - Loop over `peerCert.URIs`:
       - Skip `uri == nil`.
       - Check `strings.EqualFold(uri.Scheme, "spiffe")`:
         - If `expectedTrustDomain != ""` and `!strings.EqualFold(uri.Host, expectedTrustDomain)`: return `"", fmt.Errorf("%w: got %q, expected %q", ErrInvalidTrustDomain, uri.Host, expectedTrustDomain)`.
         - If `uri.Path == ""` or `uri.Path == "/"`: return `"", ErrMalformedSPIFFEURI`.
         - Return `uri.String()`, `nil`.
     - Return `"", ErrMissingSPIFFEID`.

## Must-Haves
### Truths
- Workload connections terminate on dedicated port `:9443` configured with `tls.RequireAndVerifyClientCert` against the Aegis Root CA pool; connections without valid certificates fail at the TLS layer.
- Workload identity is extracted strictly from `r.TLS.PeerCertificates[0].URIs` matching `spiffe://aegis.local/...`; Common Name and ingress headers are ignored.
- Inbound requests presenting user Bearer JWT tokens on the workload listener port `:9443` are rejected immediately with HTTP 401 Unauthorized (`AMBIGUOUS_CREDENTIALS`), eliminating Confused Deputy principal selection.
- Development PKI generation runs in pure Go in under 5 milliseconds without external CLI dependencies (`openssl`, `cfssl`).
