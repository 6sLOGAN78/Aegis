# Plan 02-04: End-to-End Workload Authentication and Bypass Prevention Validation Tests

<threat_model>
### Plan 02-04 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 02-04 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Unauthorized client connects to workload listener port `:9443` using a self-signed certificate, expired certificate, or certificate signed by a rogue untrusted CA. | Go TLS stack terminates the connection during the TLS handshake via `tls.RequireAndVerifyClientCert` against the Aegis Root CA pool (AUTH-02, Invariant 4). | Automated test in `tests/security/workload_identity_test.go` verifying TLS handshake failure with unknown CA. |
| **Spoofing (S)** | Peer container on the internal bridge network connects directly to `payments:8082` presenting its own workload certificate (`spiffe://aegis.local/workload/orders`) to execute an unauthorized payment. | Backend middleware checks that peer certificate SPIFFE ID matches `spiffe://aegis.local/ns/gateway/sa/aegis-gateway`. Peer workload certificates fail with HTTP 403 Forbidden (BYP-02, Invariant 12). | Automated test in `tests/integration/bypass_test.go` verifying direct peer workload connection rejection. |
| **Tampering (T)** | Authenticated workload `orders` attempts to access administrative endpoints (`/api/admin/users`) or mutate unapproved resources. | In-memory OPA policy evaluates workload input (`kind: "workload"`, `id: "spiffe://aegis.local/workload/orders"`). Rule 5 allows only `POST /api/payments`; explicit rule `DENIED_WORKLOAD_ADMIN_FORBIDDEN` rejects admin access with HTTP 403 Forbidden (POL-03, Invariant 3). | Automated test in `tests/security/workload_identity_test.go` asserting HTTP 403 Forbidden with exact reason code `DENIED_WORKLOAD_ADMIN_FORBIDDEN`. |
| **Repudiation (R)** | Workload requests succeed or fail without audit event records or request correlation IDs. | Reverse proxy assigns UUID v4 `X-Request-ID` and audit middleware records decision outcome, reason code, and duration for every workload evaluation. | Header assertion in `tests/security/workload_identity_test.go` verifying `X-Request-ID` on all responses. |
| **Information Disclosure (I)** | Direct bypass attempts or policy denial responses leak internal container hostnames, IPs, or stack traces. | Gateway and microservice middleware format errors using sanitized RFC 7807 problem details without internal implementation leaks. | Assertion on JSON problem details schema across all negative tests. |
| **Denial of Service (D)** | Gateway or microservice deadlock under concurrent workload requests and race conditions during certificate parsing. | All tests run with Go race detector (`go test -race`) to ensure thread-safe operation. | Clean exit code 0 under `go test -race` for entire test suite. |
| **Elevation of Privilege (E)** | External attacker or host process dials backend container ports directly, bypassing the gateway reverse proxy entirely. | Backend containers bind no host ports in Docker Compose (`ports:` omitted). Direct dials from host fail immediately (BYP-01, BYP-03). | Container port mapping inspection in `tests/integration/bypass_test.go` verifying zero published host ports. |
</threat_model>

## Executive Summary

Plan 02-04 provides the final verification wave of Phase 2, delivering comprehensive automated test suites that validate all six phase requirements (GW-05, AUTH-02, AUTH-03, AUTH-05, BYP-02, BYP-03) and prove adherence to non-negotiable security invariants 2, 3, 4, 5, 8, and 12.

The plan constructs:
1. An exhaustive workload identity security suite (`tests/security/workload_identity_test.go`) validating mTLS client certificate enforcement on `:9443`, SPIFFE URI SAN extraction, strict rejection of Bearer tokens on the workload port (AUTH-03), and OPA workload authorization policy enforcement (Rule 5 allow for `orders` calling `payments`, explicit deny for `orders` calling `admin`).
2. An end-to-end integration test suite (`tests/integration/bypass_test.go`) executing in the Docker Compose environment, proving that backend microservices expose zero published host ports, direct lateral container-to-container calls fail with TLS handshake failure or HTTP 403, and gateway-mediated requests succeed over upstream mTLS with signed `X-Aegis-Assertion` headers.
3. Makefile automation targets providing reproducible single-command test execution (`make test-workload`, `make test-security`, `make test-bypass`).

## Must-Haves
### Truths
- Authenticated workload `orders` presenting valid SPIFFE client certificate can invoke `POST /api/payments` through the gateway (HTTP 200).
- Authenticated workload `orders` attempting to access administrative endpoints (`/api/admin/users`) is rejected with HTTP 403 Forbidden (`DENIED_WORKLOAD_ADMIN_FORBIDDEN`).
- Requests presenting user Bearer JWT tokens on the workload listener port `:9443` are rejected with HTTP 401 Unauthorized (`AMBIGUOUS_CREDENTIALS`).
- Direct lateral calls between containers on the Docker network without the gateway's client certificate and valid signed assertion fail with TLS handshake failure or HTTP 403 Forbidden.
- Backend microservices publish zero external host ports to the Docker host network.
