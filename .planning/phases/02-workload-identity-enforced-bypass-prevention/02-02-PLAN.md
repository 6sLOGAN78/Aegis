# Plan 02-02: Short-Lived Signed Backend Assertion JWT Generator (aegis-gateway) and Gateway Client mTLS Transport

<threat_model>
### Plan 02-02 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 02-02 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Malicious internal caller fabricates an assertion header (`X-Aegis-Assertion`) claiming to be `aegis-gateway`, using `alg: none` or an untrusted signing key. | `AssertionVerifier` enforces `alg: EdDSA` with standard `ed25519.PublicKey` validation. Tokens with mismatched issuers, invalid signatures, or untrusted algorithms are rejected immediately (AUTH-05, Invariant 5). | Negative security tests in `tests/security/assertion_security_test.go` verifying rejection of forged signatures and `alg: none`. |
| **Spoofing (S)** | Gateway connects to upstream backends over plain HTTP or without verifying server certificates, exposing traffic to internal MITM interception. | Reverse proxy upstream transport enforces mutual TLS with `InsecureSkipVerify: false` against internal Root CA pool; presents gateway SPIFFE client certificate (`spiffe://aegis.local/ns/gateway/sa/aegis-gateway`) (GW-05, Invariant 4). | Automated test in `internal/proxy/proxy_test.go` asserting mutual certificate verification during upstream dispatch. |
| **Tampering (T)** | Stolen assertion token minted for `orders` service is replayed against `admin` service, or HTTP method/path is modified in transit. | Claims bind token to recipient service (`aud: <target-service>`), HTTP method (`method: POST`), and canonical path (`path: /api/orders`). Verifier rejects audience, method, or path mismatches (AUTH-05). | Table-driven tests in `internal/identity/assertion_test.go` and `tests/security/assertion_security_test.go` testing replay across services. |
| **Repudiation (R)** | Assertion tokens are reused across distinct requests without unique tracking nonces. | Each assertion embeds a cryptographically random UUID v4 `jti` (claim `id`) and request correlation ID `req_id` (`X-Request-ID`), creating distinct nonces for every forwarded request. | Unit test verifying distinct `jti` nonces on sequential assertions for the same caller. |
| **Information Disclosure (I)** | Gateway forwards raw ingress user bearer tokens (`Authorization`) or client `X-Aegis-*` headers to backend microservices, enabling lateral credential theft. | Reverse proxy `Rewrite` hook unconditionally scrubs incoming `Authorization` and all client-supplied `X-Aegis-*` headers before dispatch (GW-04, Invariant 8). | Negative test in `internal/proxy/proxy_test.go` asserting backend never receives client bearer tokens or client headers. |
| **Denial of Service (D)** | Reverse proxy allocates a new `http.Transport` per request or per route, exhausting ephemeral ports and file descriptors under load. | Reverse proxy uses a single, shared, connection-pooled `*http.Transport` with `MaxIdleConns: 1000`, `MaxIdleConnsPerHost: 100`, and `IdleConnTimeout: 90s` (Pitfall 4). | Connection reuse test in `internal/proxy/proxy_test.go` verifying idle connection pooling across multiple sequential requests. |
| **Elevation of Privilege (E)** | Adversary uses an intercepted assertion token indefinitely to access private backend APIs. | Assertion lifetime is strictly bounded to `<= 15 seconds` (`exp: now + 15s`); backends reject expired tokens outside 5s clock leeway window (AUTH-05). | Unit test verifying expired token rejection (>20s past mint time). |
</threat_model>

## Executive Summary

Plan 02-02 delivers the cryptographic bridge between the edge policy enforcement point and private backend microservices: short-lived, audience-bound backend assertion JWTs and upstream mutual TLS transport. Pursuant to ADR-0003 and Invariant 5, raw external user credentials and workload certificates are never forwarded to private backends. Instead, upon successful OPA policy authorization, the gateway mints a short-lived (<=15s) Ed25519-signed JWT assertion (`X-Aegis-Assertion`) cryptographically bound to the target microservice, HTTP method, canonical path, and request correlation ID.

Furthermore, Plan 02-02 equips the reverse proxy with an upstream mutual TLS `http.Transport` configured with the gateway's client certificate (`spiffe://aegis.local/ns/gateway/sa/aegis-gateway`) and the internal Root CA pool (`InsecureSkipVerify: false`). To prevent ephemeral port exhaustion under high load, a single shared connection-pooled transport is utilized across all proxy routes. Finally, Plan 02-02 integrates assertion minting into the gateway's request pipeline (`cmd/gateway/main.go`) and provides a comprehensive negative security test suite verifying assertion integrity, audience separation, and replay prevention.

## Must-Haves
### Truths
- On every authorized request forwarded to upstreams, the gateway mints a short-lived (<=15s) Ed25519-signed JWT assertion (`X-Aegis-Assertion`) with issuer `aegis-gateway`.
- Assertion JWTs are cryptographically bound to target service audience (`aud`), HTTP method, validated canonical path, request ID, and caller principal context.
- Assertions with forged signatures, mismatched audiences, mismatched methods, tampered paths, or expired lifetimes are rejected immediately.
- Reverse proxy forwards requests over mutual TLS with verified server certificates (`InsecureSkipVerify: false`) using a shared, connection-pooled `*http.Transport`.
- Inbound `Authorization` bearer tokens and client-supplied `X-Aegis-*` headers are stripped before forwarding.
