Parse JSON on the host with jq. Operator login captures csrf_token from the body and the aegis_session value from the Set-Cookie header, and later calls send explicit `Cookie: aegis_session=<id>` and `X-CSRF-Token` headers (the cookie is Secure so a cookie jar would drop it).

Steps, each printing `PASS: <name>` or `FAIL: <name> (<detail>)`; the script keeps going, counts hard failures, and exits 1 at the end if any hard check failed, else 0:

AUDIT: baseline `select count(*) from audit_events` via `docker compose -f "$FILE" exec -T postgres psql -U aegis -d aegis -tAc ...`; send 30 allowed `GET /api/orders` requests (5 for non-distributed profiles) so round-robin reaches every distributed gateway; poll up to 30 seconds until the count exceeds the baseline; then, for every service reported by `docker compose -f "$FILE" config --services` that matches `^audit-worker`, run the per-worker cursor check described next (each worker drained from its own spool; B3). The per-worker check must not be a single instant test: a slower worker would give a false FAIL, and existence alone does not show an advancing cursor. For each worker: (a) retry for up to 30 seconds (1s interval) until `docker compose -f "$FILE" exec -T <worker> cat /var/log/aegis/wal/wal.cursor` succeeds and is non-empty, store that content as sample 1 (FAIL with the worker name if it never appears); (b) after all workers have sample 1, send a second batch of allowed `GET /api/orders` requests (same count as the first batch) and wait for the total `audit_events` count to exceed the count measured after the first batch (up to 30 seconds); (c) retry for up to 30 seconds per worker until the wal.cursor content differs from sample 1 (sample 2 != sample 1), PASS only then, FAIL naming the worker otherwise. Compare content as the raw string, do not parse it. State in the PASS line that this proves drain wiring and an advancing cursor per spool, not AUD-03.
5. A4 (assumption, soft): after capturing a fresh developer token, POST quarantine for principal `usr_developer_01`; re-request `GET /api/orders` with that token up to 10 times over 10 seconds; print `A4 RESULT: PASS (HTTP <code>)` if a non-2xx deny (401 or 403) is observed, else `A4 RESULT: FAIL (HTTP <code>, quarantined user still allowed; record in SUMMARY, out-of-scope causes are the missing jti / encoded SPIFFE key / B8 gaps, do not fix in this phase)`.
