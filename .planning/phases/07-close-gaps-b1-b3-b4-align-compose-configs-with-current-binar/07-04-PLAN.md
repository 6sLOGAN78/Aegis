<objective>
Fix the distributed profile: one audit worker per gateway spool (B3), the Redis address on the control plane (B4), dead env removal, gateway grace period and readiness ordering with the seed.

Purpose: Today `audit-worker` mounts only `aegis_wal_spool_1`; the spools of gateway-2 and gateway-3 are never read, grow to the 90% gate, and `/readyz` returns SPOOL_SATURATED so HAProxy ejects those gateways. The audit worker reads exactly one flat directory with one `wal.cursor`, so mounting several spools into one worker silently ingests nothing and sharing one volume across gateways interleaves writes. The config-only answer (S4) is three workers, no Go change.
Output: edited `docker-compose.distributed.yml`.

Assumptions (orchestrator defaults, user can overturn): S4 three workers via a shared `x-audit-worker` anchor; S5; S6; S7 no port changes. Known cost: 3 worker DB pools (MaxConns 10 each = 30 connections against Postgres default max_connections 100; the 100 figure is assumption A2, ASSUMED). A multi-directory worker is out of scope (later closure group).
</objective>
