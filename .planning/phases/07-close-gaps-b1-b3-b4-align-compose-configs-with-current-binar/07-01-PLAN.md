<objective>
Create the one non-pure-config artifact of this phase: the `seed` one-shot image (Dockerfile target plus `seed.sh`) that loads routes and policy into the control plane through its existing REST API.

Purpose: No binary reads `policies/data/routes.json` or `policies/rego/authz.rego` (POL-03 is out of scope), and the control plane bootstraps an empty deny-all snapshot v1. Without this seed the rewritten MVP stack can start and become ready but can never serve an allowed request, so `TestMVPEndToEnd`, the quarantine denial check (A4) and any audit evidence (only allowed requests reach the WAL) cannot run. This is a workaround, not a POL-03 fix; POL-03 stays partial.
Output: `deployments/compose/seed/seed.sh`, a `seed` target appended to `deployments/compose/Dockerfile`.

Assumption (orchestrator default S3, user can overturn): ship the seed rather than a "boots and denies" MVP profile. If overturned, plans 07-03/07-04 drop the `seed` service and 200-path tests are marked blocked on POL-03.
No Go source under cmd/ or internal/ is changed (S9).
</objective>

<!-- Control plane REST contract the seed must follow (verified in RESEARCH.md against the live binary). -->
Base: AEGIS_CP_URL (compose value http://control-plane:8084).
POST /control/v1/auth/login  body {"username","password"} -> 200 JSON {"username","role","csrf_token","expires_at"} + Set-Cookie: aegis_session=<id>; Secure; HttpOnly

POST /control/v1/routes  body RouteCreateRequest JSON tags: route_id, service_id, http_method, path_template, upstream_url, upstream_spiffe_id, rate_limit_rps, rate_limit_burst, timeout_ms, requires_workload_mtls  -> 201 (upsert; 400 INVALID_ROUTE if burst < rps)

POST /control/v1/policies/{id}/publish  header If-Match: "<current snapshot version>" (quoted; "*" also accepted) -> 200 with ETag header; on 412 the response carries ETag: "<current>" (set before the 412 is written)
Required operator role: sec-ops. Demo operator admin / admin-secret (internal/control/auth.go) is passed in via env, never a literal in the script.
Idempotency-Key header is optional (must be a UUID if sent); the seed does not use it.
policies/data/routes.json entry shape: route_id, service_id, http_method, path_template, upstream_url, upstream_spiffe_id, rate_limit{requests_per_second,burst}, timeout{request_timeout_ms,upstream_timeout_ms}, requires_workload_mtls

  <action>
Create `deployments/compose/seed/seed.sh` as a POSIX sh script (`#!/bin/sh`, `set -eu`, no bashisms, no reliance on `pipefail`; write intermediate responses to files under a `mktemp -d` directory removed by a `trap ... EXIT`). Section banners use the `=== Section ===` style from scripts/generate.sh and go to stderr so stdout stays machine-readable.

Environment inputs (S3 assumption, document in a header comment): `AEGIS_CP_URL` (default `http://control-plane:8084`), `AEGIS_SEED_USER`, `AEGIS_SEED_PASSWORD` (both REQUIRED, no default, script exits 2 with a message naming the missing variable and never echoes the value), `AEGIS_SEED_POLICY_DIR` (default `/app/policies`), `AEGIS_SEED_POLICY_ID` (default `mvp-authz`), `AEGIS_SEED_WAIT_SECONDS` (default `60`), `AEGIS_SEED_DRY_RUN` (when `1`: print the transformed route payloads and exit 0 before any network call or credential check).

Behavior, in order:
0. Ordering: after parsing env, (a) if `AEGIS_SEED_DRY_RUN=1`, run the step 1 route transform (the only file read in dry-run), print, and exit 0; (b) otherwise, immediately and before ANY file read or network call (in particular before `/app/policies` or `$AEGIS_SEED_POLICY_DIR` is touched), check that `AEGIS_SEED_USER` and `AEGIS_SEED_PASSWORD` are set and non-empty and exit 2 naming the missing variable if not; (c) only then run step 1 and the remaining steps. This guarantees the missing-password acceptance command fails on the credential check even on a host that has no `/app/policies`.
   Implement step 1 as a shell function shared by the dry-run path and the normal path.
1. Route transform with `jq -c` over `$AEGIS_SEED_POLICY_DIR/data/routes.json`, producing one compact JSON object per route with exactly these keys: route_id, service_id, http_method, path_template, upstream_url, upstream_spiffe_id, rate_limit_rps (from rate_limit.requests_per_second), rate_limit_burst = the maximum of rate_limit.burst and rate_limit.requests_per_second (trap: the API rejects burst < rps and routes.json has burst < rps on all 5 routes), timeout_ms (from timeout.upstream_timeout_ms), requires_workload_mtls. In dry-run mode print these lines on stdout and exit 0.
2. Wait loop: poll `$AEGIS_CP_URL/control/v1/auth/me` with `curl -s -o /dev/null` once per second until curl itself succeeds (any HTTP status, a 401 is fine) or `AEGIS_SEED_WAIT_SECONDS` elapses (then exit 1).
3. Login: build the body with `jq -n --arg` (no string interpolation), POST to `/control/v1/auth/login` with `curl -s -D <headers file> -o <body file> -w '%{http_code}'`. Require 200. Read `csrf_token` from the body with jq. Read the session id from the `Set-Cookie: aegis_session=` response header (case-insensitive match, strip `\r` and everything after `;`). Never print the cookie, the CSRF token or the password. Do NOT use a curl cookie jar or `-b`/`-c` cookie flags: the cookie is `Secure` and curl drops it over plain HTTP. Send `-H "Cookie: aegis_session=$SID"` and `-H "X-CSRF-Token: $CSRF"` explicitly on every later call (helper function `cp_call METHOD PATH BODYFILE`).
4. Routes: read the transformed lines from a file via redirection into a `while read -r` loop (not a pipe, so `exit 1` inside the loop is not swallowed by a subshell). POST each to `/control/v1/routes`; any status other than 201 (or 200) prints `route <route_id> failed: HTTP <code>` plus the response body and exits 1. After the loop assert the number of posted routes equals `jq length` of routes.json, else exit 1.
5. Policy: build `{policy_id:$AEGIS_SEED_POLICY_ID, name:"authz.rego", source_rego:<file contents>}` with `jq -n --arg id ... --rawfile s "$AEGIS_SEED_POLICY_DIR/rego/authz.rego"` (no string interpolation of rego into JSON). POST to `/control/v1/policies`; require 201 or 200.
6. Publish: POST `/control/v1/policies/$AEGIS_SEED_POLICY_ID/publish` with `If-Match: "1"` first. On 412, read the `ETag` header from the dumped response headers (strip quotes and `\r`) and retry exactly once with `If-Match: "<that value>"`. Any other non-200 or a second 412 exits 1. Re-running against a persisted postgres_data volume therefore works: routes and drafts are upserts and each run publishes one new snapshot version (document this in the header comment; do not add skip logic).
7. Print `seed complete: <n> routes, policy <id>, snapshot version <ETag value>` to stderr and exit 0.

Every curl call uses `--max-time 15`. All failure paths exit non-zero (this is what lets compose `service_completed_successfully` gate the gateway; per T-07-05). No credential literals appear anywhere in the script.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| seed container -> control-plane REST (:8084, aegis-internal network) | Operator-credentialed management calls; plain HTTP inside the private compose network |
| compose env -> seed process | Operator demo credentials cross as env vars |
| repo files (routes.json, authz.rego) -> JSON payloads | Untrusted-format file content turned into API JSON |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Information disclosure | Seed credentials (admin / admin-secret) in compose env | accept | Existing hardcoded demo operator (internal/control/auth.go, known tech debt, no new secret introduced, nothing marked production). Script has no literals, requires env, never prints password, cookie or CSRF token. |
| T-07-02 | Tampering | JSON construction from rego and routes | mitigate | All JSON built with `jq -n --arg/--rawfile` and a `jq -c` transform; no shell string interpolation of file content into JSON (ASVS V5). |
| T-07-03 | Elevation of privilege | Seed uses a sec-ops session | mitigate | One-shot container, `restart: "no"`, no published ports (enforced in compose by 07-03/07-04 and the 07-02 test); session is not persisted beyond the process; no new endpoints or RBAC changes. |
| T-07-04 | Spoofing / session handling | `Secure` session cookie over plain HTTP | mitigate | Explicit Cookie and X-CSRF-Token headers; cookie flags are not weakened and no cookie jar is used (ASVS V3). |
| T-07-05 | Elevation (fail-open drift) | Half-seeded snapshot (routes 400, publish with zero routes) | mitigate | Every non-2xx exits 1 and compose gates the gateway on `service_completed_successfully`; route count asserted against routes.json. |
| T-07-SC | Tampering (supply chain) | Alpine `jq` apk in the seed image | accept | Official Alpine 3.21 main repository package; no npm/pip/cargo install so no slopcheck applies; availability verified by the image build in plan 07-05 (A1 [ASSUMED]). |
