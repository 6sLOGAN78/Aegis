<objective>
Lay the data-model foundation for Phase 8: the explicit record type (D-03), the normalization chokepoint that stops hostile field values from wedging the worker (D-18), the worker changes that persist both, the additive migration for the suppressed-count summary rows, and the three one-line contract updates that add `denial` to the event_type enum.

Purpose: every later plan writes records that carry `event_type`, and denial rows carry attacker-controlled strings (decoded URL path with NUL bytes, arbitrary HTTP method tokens). Research reproduced both poisoning cases against Postgres 14: one rejected row rolls back the whole batch, the cursor never advances and the worker retries forever. The worker must therefore be hardened before any producer exists.
Output: event.go (fields, constants, Normalize), worker.go (typed insert, 20 arguments, normalization), migration 000003, contract enums, tests for all of it, and the 20-argument update of both hard-coded audit-insert test helpers (internal/audit/worker_test.go and tests/dr/dr_test.go).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client request -> audit record | method, decoded URL path, principal id and similar strings are attacker-controlled and end up in audit rows |
| spool file -> audit worker -> PostgreSQL | worker parses framed JSON and inserts it; a rejected row aborts the whole batch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Denial of service / Tampering | worker.ProcessBatch fed a NUL byte or an over-width value (poison row) | mitigate | CompletionEvent.Normalize() in the worker before queuing (strip NUL, ToValidUTF8, clip to column widths, 2048-byte path cap); tested with NUL, 28-char method, 200-char principal (D-18) |
| T-08-02 | Tampering | non-UUID request_id or event_id reaching UUID columns | mitigate | worker replaces unparseable ids with uuid.NewString() so the batch cannot be rejected |
| T-08-03 | Repudiation | a denial or completion stored under the wrong type | mitigate | explicit event_type allowlist {decision, completion, denial}; unknown values fall back to the status guess; tests assert literal type per case (D-03) |
| T-08-04 | Information disclosure | normalization cannot add data | accept | Normalize only removes or truncates; no new data source |
| T-08-06 | Tampering | Normalize deliberately skips PrincipalRoles (JSONB marshals any string safely, and roles come from verified token claims, not raw request bytes) | accept | considered and accepted: roles are marshalled with json.Marshal in the worker, which escapes NUL and invalid UTF-8; no column-width limit applies to JSONB |
| T-08-07 | Tampering | malformed event_id or request_id is replaced with a fresh uuid.NewString() rather than rejected | accept | considered and accepted: a replaced request_id loses linkage for that one hostile record only, and a replaced event_id is the only way to keep the batch alive; the replacement is never attacker-chosen |
| T-08-08 | Tampering | contract enum edits (OpenAPI, generated Go constant, dashboard TypeScript union) go slightly beyond the literal worker/spool boundary of the phase | accept | considered and accepted: three one-line additions of the value denial so the published contract does not lie once denial rows exist; no dashboard display code, no audit API behavior and no audit_repo.go change |
| T-08-05 | Tampering | migration 000003 on a live partitioned table | accept | additive nullable column (research verified ADD COLUMN works on the partitioned parent); worker holds its cursor and loses nothing if it starts before the control plane migrates |
</threat_model>
