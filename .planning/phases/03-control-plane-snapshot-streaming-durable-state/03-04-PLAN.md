# Plan 03-04: Local Append-Only Disk WAL Spool with Pre-Forward fsync, 90% Saturation Gate, and Async Audit Worker

<threat_model>
### Plan 03-04 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 03-04 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Unprivileged local process writes rogue records to WAL directory or injects forged log files. | Spool directory permissions are restricted to `0700` and files to `0600`; WAL records require binary magic header (`0xAE615001`), CRC32 checksum, and length prefix framing. | Unit tests in `internal/audit/spool_test.go` asserting rejection of records with invalid magic bytes or mismatched CRC32. |
| **Tampering (T)** | Power outage, abrupt SIGKILL, or partial write corrupts WAL record on disk. | `internal/audit/spool.go` frames every record with 32-bit CRC32 checksum; worker validates CRC32 before batching; corrupted records trigger recovery and quarantine (AUD-01). | Unit test writing truncated or bit-flipped bytes to WAL file; assert worker detects corruption and preserves clean records. |
| **Repudiation (R)** | A permitted state-mutating request (`POST /api/payments`) succeeds on backend, but gateway crashes before logging the event. | Mandated by Invariant 10: Gateway serializes authorization decision, appends to local append-only WAL on disk, and executes synchronous `os.File.Sync()` (`fsync`) **before** dispatching upstream request. If disk append or `fsync` fails, upstream is never dispatched (AUD-01, ADR-0006). | Unit and fault-injection tests verifying WAL contains decision record before upstream mock receives request. |
| **Information Disclosure (I)** | Audit records on disk read by unauthorized users or leaked in error responses. | Local spool directory enforces POSIX permissions `0700` owned by gateway user; database error messages during ingestion are suppressed from data plane responses. | Filesystem permission assertions in unit tests. |
| **Denial of Service (D)** | Extended PostgreSQL database outage causes local WAL files to fill gateway disk, crashing the host OS. | Mandated by Invariant 10: Gateway actively tracks spool volume capacity; if disk utilization reaches 90% capacity, the saturation safety gate triggers immediately: halts admission of permitted requests with HTTP 503 (`AUDIT_SPOOL_SATURATED`) (AUD-02). | Security failure test in `tests/failure/spool_saturation_test.go` simulating 90% disk utilization; assert gateway returns HTTP 503 and drops zero audit records. |
| **Elevation of Privilege (E)** | Permitted request forwarded to backend while audit subsystem is failing or disabled, producing untracked mutations. | Gateway reverse proxy dispatch is strictly blocked until `spool.AppendPreForward()` returns nil error; failures return HTTP 500/503 without forwarding. | Fault injection test asserting zero backend calls when WAL write returns simulated I/O error. |
</threat_model>

## Executive Summary

Plan 03-04 implements durable audit logging and non-repudiation for the Aegis gateway grid. In accordance with Invariant 10 and ADR-0006, every permitted request through the gateway must have an immutable, durable audit record committed to non-volatile storage before any request is forwarded to a backend microservice.

To satisfy the sub-20ms latency budget without creating a hard dependency on central database availability on the request hot path, the gateway writes decision events to a local append-only Write-Ahead Log (WAL) on disk, forcing durability via synchronous `os.File.Sync()` (`fsync` syscall). An asynchronous background worker (`audit-worker`) tails WAL segments, batches events, and commits them to partitioned PostgreSQL (`audit_events`) with deduplication (`ON CONFLICT DO NOTHING`) and persistent cursor checkpoints (`wal.cursor`). To prevent disk exhaustion during database outages, a 90% saturation circuit breaker halts new admissions with HTTP 503 before disk capacity is exhausted.

- `internal/audit/spool.go` exports:
  - Sentinel error `ErrSpoolSaturated = errors.New("audit spool saturated (>= 90% capacity)")`.
  - Sentinel error `ErrCorruptedRecord = errors.New("wal record checksum mismatch")`.
  - Constant `MagicHeader uint32 = 0xAE615001`.
  - `DiskSpoolConfig` struct: `SpoolDir string`, `MaxSegmentBytes int64` (default 16MB), `VolumeQuotaBytes int64` (default 1GB).
  - `DiskSpool` struct managing active segment file, segment rotation, and file locking.
  - `NewDiskSpool(cfg DiskSpoolConfig) (*DiskSpool, error)`: creates spool directory with `0700` permissions.
  - `AppendPreForward(event *CompletionEvent) error`:
    - Checks 90% spool saturation gate (via filesystem stats and configured quota bytes); returns `ErrSpoolSaturated` if $\ge 90\%$.
    - Encodes event to JSON.
    - Computes 32-bit CRC32 checksum (`crc32.ChecksumIEEE`).
    - Writes framed record: `[Magic: 4B][CRC32: 4B][Length: 4B][Payload: NB][\n: 1B]`.
    - Forces synchronous non-volatile disk write via `file.Sync()` (`fsync` syscall) before returning (AUD-01).
    - Rotates segment file when current segment size exceeds `MaxSegmentBytes`.
  - `Close() error`: closes active file cleanly.

  - Preserves dynamic `snapshot.Manager` (Plan 03-02) and Redis revocation/rate limiting (Plan 03-03).
  - Instantiates `DiskSpool` during gateway initialization.
  - In both user and workload request handlers: when OPA policy evaluates `allow == true`:
    - Generates pre-forward decision record via `event := ac.ToCompletionEvent(r.Method, clientIP, state.Version)`.
    - Calls `spool.AppendPreForward(event)` **before** executing `rp.ServeHTTP(w, r)`.

    - If write or `fsync` fails: writes HTTP 500 / 503 error, logs failure, and returns without upstream dispatch (Invariant 10).

## Must-Haves
### Truths
- Permitted requests append authorization decision records to a local append-only disk WAL and execute synchronous `os.File.Sync()` (`fsync`) before upstream network dispatch (Invariant 10).
- If disk append or `fsync` fails, the upstream backend request is never dispatched; client receives HTTP 500 / 503.
- The 90% spool saturation gate halts admissions of permitted requests with HTTP 503 Service Unavailable (`AUDIT_SPOOL_SATURATED`) before disk capacity is exhausted.
- The asynchronous audit worker delivers WAL records to PostgreSQL partitioned `audit_events` in batches with deduplication (`ON CONFLICT DO NOTHING`).
- The persistent cursor offset checkpoint (`wal.cursor`) advances only after PostgreSQL successfully commits the batch, guaranteeing at-least-once delivery.
