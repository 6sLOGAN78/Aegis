# Plan 03-05: Fault Injection and Restart Tests for Dependency Failure Modes

<threat_model>
### Plan 03-05 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 03-05 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Attacker exploits dependency restarts (Redis bounce, Control Plane reload) to present revoked credentials during reconnect transitions. | Data plane gateways maintain in-memory atomic state; reconnection logic operates in background without downgrading security checks; Redis check enforces strict 200ms timeout and fails closed if disconnected during reconnect (REV-04, Invariant 1). | Fault injection test verifying requests during Redis bounce return HTTP 503 rather than bypassing checks. |
| **Tampering (T)** | Network partition causes desynchronized state between control plane, gateway, and database. | Monotonic version numbers ($N+1$) and cryptographic Ed25519 signatures prevent replay of older state; gateway atomically swaps valid state or keeps previous state if incoming is corrupted (CTRL-02, Invariant 9). | Automated test verifying gateway rejects out-of-order snapshots during network partition. |
| **Repudiation (R)** | Database downtime causes WAL spool to fill up; gateway drops audit records to keep traffic flowing. | Mandated by Invariant 10: Gateway 90% spool saturation gate halts admission of permitted requests with HTTP 503 Service Unavailable (`AUDIT_SPOOL_SATURATED`) rather than dropping audit events silently (AUD-02). | Saturation fault test in `tests/failure/failure_test.go` verifying zero requests reach backends when spool is saturated. |
| **Information Disclosure (I)** | Chaos fault injection and dependency error responses leak internal infrastructure topology, connection strings, or system paths. | Gateway intercepts all dependency errors (Redis timeout, lease expiration, spool exhaustion) and formats sanitized RFC 7807 problem details without internal error details. | Assertions on response bodies in failure test suite ensuring zero infrastructure leaks. |
| **Denial of Service (D)** | Cascading dependency failure causes unbounded gateway goroutine accumulation or gateway process panic. | All external dependency calls enforce strict context timeouts (Redis 200ms, gRPC backoff jitter, WAL disk check bounds); failure paths return immediately with HTTP 503 without leaking goroutines. | Race detection and goroutine leak assertions during chaos test execution (`go test -race`). |
| **Elevation of Privilege (E)** | An attacker deliberately causes a Redis outage, severs the control-plane gRPC connection, or exhausts disk space to trigger permissive fail-open mode. | Grounded in Invariant 1: **Default deny and fail closed.** 100% of requests during dependency failure modes fail closed: Redis down -> HTTP 503 (`DEPENDENCY_OUTAGE_REDIS`), lease expired (>60s) -> HTTP 503 (`POLICY_LEASE_EXPIRED`), spool full (>=90%) -> HTTP 503 (`AUDIT_SPOOL_SATURATED`). Zero permissive fallbacks exist (CTRL-04, REV-04, AUD-02). | Comprehensive chaos test suite in `tests/failure/failure_test.go` verifying 100% fail-closed adherence across all three failure conditions. |
</threat_model>

## Executive Summary

Plan 03-05 validates the resilience and non-negotiable fail-closed security properties of Phase 3 under active fault injection and dependency failures. Grounded in Invariant 1, Invariant 9, and Invariant 10, Aegis must never produce implicit authorization, permit stale policy execution, or forward unlogged transactions during infrastructure disruptions.

This plan delivers the complete Profile 2 Hardened deployment configuration (`deployments/compose/docker-compose.hardened.yml`) orchestrating PostgreSQL 16, Redis 7.2, Control Plane, Gateway, Audit Worker, Demo Issuer, and private backend microservices with zero published host ports. It implements a unified, automated fault injection test suite (`tests/failure/failure_test.go`) systematically verifying all three core failure modes: Redis outage fail-closed (REV-04), 60-second snapshot freshness lease expiration fail-closed (CTRL-04), and 90% WAL spool saturation fail-closed (AUD-02), proving 100% adherence to zero-trust invariants.

<acceptance_criteria>
- `tests/failure/failure_test.go` implements comprehensive automated failure mode verification under `go test -race`:
  1. **TestFailure_RedisOutageFailClosed (REV-04)**:
     - Baseline: Authenticated request with valid JWT reaches mock upstream backend; returns HTTP 200.
     - Fault Injection: Redis instance is stopped / severed.
     - Verification: Subsequent requests return **HTTP 503 Service Unavailable** with RFC 7807 problem details:
       - `type: "https://aegis.local/errors/dependency-unavailable"`
       - `status: 503`
       - Reason code: `DEPENDENCY_OUTAGE_REDIS`
     - Assertion: Upstream backend receives **0** requests during the outage (100% fail-closed, zero fail-open bypass).
     - Recovery: Redis restarted; gateway resumes normal authorization within seconds.
  2. **TestFailure_SnapshotLeaseExpiryFailClosed (CTRL-04)**:
     - Baseline: Control plane streams signed 10-second freshness leases; gateway authorizes requests normally.
     - Fault Injection: Control plane gRPC connection is severed; no lease renewals received.
     - Verification (Transient window $\le 60$s): Gateway continues authorizing traffic against cached snapshot while logging degraded lease warning.
     - Verification (Hard boundary $> 60$s): Once lease renewal age exceeds 60 seconds, gateway drops readiness healthcheck (`/healthz/ready` returns 503) and all protected routes return **HTTP 503 Service Unavailable**:
       - `type: "https://aegis.local/errors/policy-lease-expired"`
       - `status: 503`
     - Assertion: No unauthenticated or stale authorization is permitted after 60 seconds.
     - Recovery: Control plane re-establishes stream and issues fresh lease; gateway immediately restores readiness and normal authorization.
  3. **TestFailure_SpoolSaturationFailClosed (AUD-02)**:
     - Baseline: Permitted requests append pre-forward decision event to local disk WAL with `fsync` before forwarding.
     - Fault Injection: Spool directory reaches 90% capacity threshold.
     - Verification: Gateway admission circuit breaker activates; subsequent permitted requests are rejected with **HTTP 503 Service Unavailable**:
       - `type: "https://aegis.local/errors/spool-saturated"`
       - `status: 503`
     - Assertion: Zero permitted requests reach upstream backends without durable audit logging (Invariant 10).
     - Recovery: Audit worker drains events to PostgreSQL and prunes archived WAL segments; spool utilization drops below 90%; gateway resumes admitting permitted traffic.
- Automated test command executes and exits with code 0:
  `go test -v -race ./tests/failure/...`

## Must-Haves
### Truths
- If Redis is down, partitioned, or times out (>200ms), 100% of protected requests fail closed with HTTP 503 Service Unavailable (`DEPENDENCY_OUTAGE_REDIS`); zero requests reach upstream backends.
- If the control plane gRPC stream is severed for >60 seconds without valid lease renewal, gateway drops readiness and fails closed with HTTP 503 Service Unavailable (`POLICY_LEASE_EXPIRED`).
- If the local audit spool volume reaches 90% capacity, gateway halts admissions of permitted requests with HTTP 503 Service Unavailable (`AUDIT_SPOOL_SATURATED`), preventing unlogged transactions.
- Zero dependency failure mode ever produces implicit authorization, stale bypass, or unlogged mutation (Invariant 1, Invariant 9, Invariant 10).
