# Plan 01-03: Mock JWT Issuer, Private Demo Microservices, Route Resolution, and Docker Compose MVP Profile

<threat_model>
### Plan 01-03 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 01-03 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Attacker presents JWT with `alg: none`, HMAC substituted key (CVE-2015-9235), forged signature, or wrong issuer/audience to impersonate users. | `TokenValidator` enforces pinned asymmetric algorithm allowlist (`EdDSA`, `RS256`, `ES256`). Rejects `none` and symmetric keys unconditionally. Validates issuer, audience, and subject with 30s clock skew tolerance (AUTH-01, Invariant 2). | Negative test suite in `tests/security/jwt_negative_test.go` asserting HTTP 401 across all malicious token variants. |
| **Tampering (T)** | Attacker supplies fabricated `Host` or `X-Forwarded-Host` headers to manipulate routing or induce Server-Side Request Forgery (SSRF). | Upstream router maps incoming requests deterministically by `(method, canonicalPath)` against static `routes.json`. Client `Host` header is completely ignored for upstream selection (GW-03, Invariant 6). | Route resolution unit tests verifying target backend URL matches configured definition regardless of client `Host`. |
| **Repudiation (R)** | Anonymous callers attempt to invoke protected business routes without cryptographic identity proof. | Gateway PEP requires valid Bearer JWT before evaluating OPA policies or dispatching upstream; anonymous calls fail closed with HTTP 401 Unauthorized (Invariant 2). | Integration test verifying anonymous request to `/api/orders` returns 401. |
| **Information Disclosure (I)** | Exposing backend microservice ports directly on the host machine enables attackers to bypass gateway authorization and read business data. | Docker Compose MVP profile publishes zero host ports for `orders`, `payments`, and `admin`. Backends attach strictly to the private `aegis-internal` network and are reachable only via the gateway (BYP-01). | Verification test asserting connection to `localhost:8081` from host machine fails with connection refused. |
| **Denial of Service (D)** | Brute-force credential stuffing or high-volume login flooding exhausts demo issuer CPU or memory. | Demo issuer enforces in-memory IP-based rate throttling (max 20 attempts per minute per IP), rejecting excess requests with HTTP 429 Too Many Requests (AUTH-04). | Unit test in `cmd/demo-issuer/main_test.go` sending 25 rapid requests and asserting HTTP 429 on the 21st attempt. |
| **Elevation of Privilege (E)** | Compromised client attempts direct microservice bypass to execute admin actions without gateway RBAC checks. | Network boundary isolation prohibits direct traffic; all calls must traverse the gateway reverse proxy which applies embedded OPA RBAC rules (BYP-01). | End-to-end integration test confirming admin routes require valid admin role token via gateway port 8080. |
</threat_model>

## Executive Summary

Plan 01-03 connects identity and upstream routing into the secure vertical slice. It implements the cryptographic JWT validator with RFC 8725 compliance and pinned algorithm allowlists (AUTH-01), the local development demo JWT issuer with seeded accounts and login rate throttling (AUTH-04), three private Go backend microservices (`orders`, `payments`, `admin`) (BYP-01), deterministic upstream route matching (GW-03), the primary gateway binary entrypoint (`cmd/gateway/main.go`), and the Docker Compose MVP profile (`docker-compose.mvp.yml`) enforcing zero published backend host ports.
