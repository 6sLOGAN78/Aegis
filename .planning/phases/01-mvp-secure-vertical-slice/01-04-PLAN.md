# Plan 01-04: Structured Completion Audit Events and Automated Negative Security Test Suite

<threat_model>
### Plan 01-04 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 01-04 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Malicious request attempts to forge client IP or request ID in audit logs by injecting forwarding headers. | Audit event captures client IP strictly from socket connection `r.RemoteAddr` and request ID from gateway-generated UUID v4, completely ignoring client-supplied headers (AUD-04, Invariant 8). | Unit test in `internal/audit/logger_test.go` verifying audit event fields are sourced from trusted context. |
| **Tampering (T)** | Log corruption or omitted required audit fields makes compliance decisions unexplainable. | Strongly typed `CompletionEvent` struct strictly mirrors `pkg/api/control/v1/types.gen.go:AuditEvent` and serializes through Go's standard library `log/slog.JSONHandler` with enforced field schema (AUD-04). | Unit test validating JSON unmarshaling and required field completeness on logged outputs. |
| **Repudiation (R)** | Malicious transactions or denied requests complete without leaving an immutable audit record. | Gateway PEP pipeline wraps the entire HTTP handler execution with a deferred completion logger, guaranteeing 100% emission of structured audit events on all responses (HTTP 200, 400, 401, 403, 429, 502) (AUD-04). | Integration test asserting completion audit event exists for every executed request across the full vertical slice. |
| **Information Disclosure (I)** | Audit log lines leak user bearer tokens, sensitive request bodies, or internal microservice credentials. | `CompletionEvent` explicitly omits raw token strings, request bodies, and passwords; records only verified `principal_id`, `roles`, route metadata, HTTP status, and duration (AUD-04). | Security assertion verifying no `Authorization` header contents appear in audit log captures. |
| **Denial of Service (D)** | Synchronous disk or database logging operations block incoming request worker threads during high traffic. | In Phase 1, completion audit logging writes structured JSON asynchronously/non-blocking to stdout via `log/slog` (PostgreSQL WAL streaming deferred to Phase 3) to maintain sub-millisecond gateway overhead. | Latency assertion ensuring audit logger introduces <0.05ms overhead per request. |
| **Elevation of Privilege (E)** | Undetected bypasses across the vertical slice allow unauthorized access to private services. | Comprehensive end-to-end integration test suite in `tests/integration/mvp_test.go` exercises all 13 Phase 1 requirements against the running Docker Compose MVP cluster. | Automated integration test run asserting developer denied admin (403), traversal rejected (400), and backend host ports unreachable. |
</threat_model>

## Executive Summary

Plan 01-04 completes Phase 1 by implementing structured completion audit logging (AUD-04) and the comprehensive automated integration test suite validating the entire Phase 1 vertical slice. It introduces the `CompletionEvent` data model mirroring the Phase 0 OpenAPI `AuditEvent` schema, an optimized `log/slog` JSON completion logger recording request duration, principal context, decision reason codes, and HTTP statuses on 100% of proxy responses. It authors the end-to-end integration suite (`tests/integration/mvp_test.go`) validating developer/finance/admin role authorization, strict zero-repair path rejection, header scrubbing, and backend network isolation (BYP-01) in Docker Compose, and establishes Makefile automation for developer workflows.

## Must-Haves
### Truths
- Every proxy response (allowed, denied, or malformed) emits a structured JSON completion audit event containing request ID, principal, route, decision, status, duration ms, and reason code.
- User with `developer` role token successfully retrieves `/api/orders` (HTTP 200) and `/api/payments` (HTTP 200), but is rejected from `/api/admin/users` with HTTP 403 Forbidden.
- Incoming requests with path traversal (`/..`), encoded separators (`%2f`, `%5c`), NUL bytes (`%00`), or duplicate slashes (`//`) are rejected immediately with HTTP 400 Bad Request without path repair.
- Inbound client-supplied `X-Aegis-*` and hop-by-hop headers are stripped; unauthenticated ingress concurrency is bounded before identity resolution.
- All three backend services (`orders`, `payments`, `admin`) run in Docker Compose with zero published host ports, preventing direct network bypass.
