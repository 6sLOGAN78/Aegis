# Plan 01-01: Go Gateway Reverse Proxy with Strict Path Rejection, Request Limits, and Header Sanitization

<threat_model>
### Plan 01-01 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 01-01 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Ingress client supplies `X-Aegis-User`, `X-Aegis-Roles`, `Forwarded`, or RFC 7230 hop-by-hop headers to forge identity or proxy routing context. | `httputil.ProxyRequest.Rewrite` hook unconditionally purges all client-supplied `X-Aegis-*` headers, `Forwarded`, `X-Forwarded-*`, and RFC 7230 hop-by-hop headers before upstream dispatch (GW-04, Invariant 8). | Negative test in `tests/security/header_spoofing_test.go` asserting mock upstream backend never receives client-supplied headers. |
| **Tampering (T)** | Path traversal (`..`, `/..`), encoded separators (`%2f`, `%5c`), duplicate slashes (`//`), or NUL bytes (`%00`) sent in HTTP request line to bypass routing or access unauthorized upstream resources. | `ValidatePathZeroRepair` inspects raw wire bytes in `r.RequestURI` before URL unescaping or router cleaning. Immediately returns HTTP 400 Bad Request without calling `path.Clean()` or auto-repairing paths (GW-02, Invariant 7). | Security test suite in `tests/security/path_traversal_test.go` asserting HTTP 400 across all traversal variants with zero upstream forwarding. |
| **Repudiation (R)** | Malformed or rejected requests go unrecorded without traceable correlation IDs. | Gateway assigns cryptographically random UUID v4 to `X-Request-ID` at socket arrival and returns RFC 7807 problem details containing request instance references (GW-01). | Header assertion in `internal/proxy/proxy_test.go` verifying UUID format on all response paths. |
| **Information Disclosure (I)** | Upstream backend connection errors leak internal container DNS names, stack traces, or socket addresses to external clients. | Reverse proxy `ErrorHandler` intercepts network failures and formats standardized RFC 7807 problem details with generic detail strings and HTTP 502 Bad Gateway status. | Test in `internal/proxy/proxy_test.go` verifying 502 response payload omits internal socket details. |
| **Denial of Service (D)** | Volumetric HTTP connection flood exhausts gateway CPU before identity resolution; oversized headers or request bodies exhaust memory. | Counting semaphore `ConcurrencyLimiter` bounds in-flight unauthenticated requests to `max_concurrent` (HTTP 429 with `Retry-After: 1`). `http.Server` enforces `MaxHeaderBytes = 16 KiB`, `ReadHeaderTimeout = 5s`, and body capped via `http.MaxBytesReader` to 1 MiB (REV-02, GW-01). | Concurrency flood test in `internal/proxy/limiter_test.go` asserting HTTP 429 rejection; listener limit test asserting 431/400 for oversized headers/bodies. |
| **Elevation of Privilege (E)** | Path traversal or separator ambiguity allows unprivileged callers to reach private admin routes via impedance mismatch. | Gateway forwards the exact identical validated canonical path bytes (`pr.Out.URL.Path = canonicalPath; pr.Out.URL.RawPath = ""`) to upstream backends, eliminating parser divergence (Invariant 7). | End-to-end traversal assertion ensuring no traversal variant reaches mock upstream handlers. |
</threat_model>

## Executive Summary

Plan 01-01 constructs the edge data-plane foundation of Aegis: the Go HTTP reverse proxy and ingress security perimeter. It establishes strict runtime configuration with enforced edge listener limits (16 KiB headers, 1 MiB body, cryptographically random UUID request IDs), unauthenticated ingress concurrency throttling via counting semaphores (REV-02), strict zero-repair path validation rejecting traversal and encoding anomalies with HTTP 400 Bad Request on raw wire bytes (GW-02), and modern Go 1.20+ `httputil.ReverseProxy.Rewrite` dispatch with unconditional header scrubbing (GW-04).

<acceptance_criteria>
- `internal/proxy/validator.go` implements `ValidatePathZeroRepair(r *http.Request) (string, error)` inspecting raw wire bytes from `r.RequestURI` before standard library unescaping.
- Rejects paths containing:
  - Dot-segments: `/../`, `/..` suffix, `..` exact, `/./`, `/.` suffix, `%2e%2e`, `.%2e`, `%2e.`
  - Encoded directory separators: `%2f`, `%2F`, `%5c`, `%5C`, and literal `\`
  - Duplicate slashes: `//`
  - NUL bytes: literal `\x00` and encoded `%00`
  - Non-absolute paths: paths not starting with `/`
- Returns typed errors: `ErrPathContainsTraversal`, `ErrPathContainsEncodedSlash`, `ErrPathContainsDoubleSlash`, `ErrPathContainsNulByte`, `ErrPathInvalidPrefix`.
- Never invokes `path.Clean()` or mutates malicious paths before evaluation.
- `tests/security/path_traversal_test.go` runs parameterized table-driven tests against an HTTP test server verifying immediate HTTP 400 Bad Request with RFC 7807 problem details for all traversal variants, and HTTP 200/404 for valid paths.
- Security test command exits with code 0:
  `go test -v -race ./tests/security/ -run TestZeroRepairPathValidation`
</acceptance_criteria>

<action>

   - Declare package `proxy`.
   - Define sentinel errors:
     - `ErrPathContainsTraversal = errors.New("path contains traversal dot-segments")`
     - `ErrPathContainsEncodedSlash = errors.New("path contains encoded directory separators")`
     - `ErrPathContainsDoubleSlash = errors.New("path contains duplicate slashes")`
     - `ErrPathContainsNulByte = errors.New("path contains NUL bytes")`
     - `ErrPathInvalidPrefix = errors.New("path does not start with /")`
   - Implement `ValidatePathZeroRepair(r *http.Request) (string, error)`:

     - Inspect `rawPath` and case-insensitive lowercased copy `lower`.
     - Detect `//` -> return `ErrPathContainsDoubleSlash`.
     - Detect `\x00` or `%00` -> return `ErrPathContainsNulByte`.
     - Detect `%2f`, `%5c`, or `\` -> return `ErrPathContainsEncodedSlash`.

     - Detect absence of leading `/` -> return `ErrPathInvalidPrefix`.
     - Return unmodified `rawPath` string on success.

## Must-Haves
### Truths
- Requests containing path traversal dot-segments (`..`, `%2e%2e`), encoded slashes (`%2f`, `%5c`), duplicate slashes (`//`), or NUL bytes (`%00`) are rejected immediately with HTTP 400 Bad Request on raw wire bytes without calling `path.Clean()`.
- Client-supplied `X-Aegis-*`, `Forwarded`, and hop-by-hop headers are unconditionally stripped before forwarding to upstream backends.
- Inbound requests receive cryptographically random UUID v4 `X-Request-ID` headers; 16 KiB header limits and 1 MiB body limits are enforced.
- Unauthenticated ingress concurrency is bounded by a counting semaphore returning HTTP 429 Too Many Requests upon saturation.
