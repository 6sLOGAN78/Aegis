# Plan 01-02: Embedded OPA Engine, Precompiled Query Evaluator, and Static Local Snapshot Loader

<threat_model>
### Plan 01-02 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 01-02 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Caller presents anonymous request or malformed principal object with empty ID attempting to bypass identity checks. | Embedded Rego policy rules explicitly evaluate `invalid_principal if not input.principal.id` and `invalid_principal if input.principal.id == ""` returning `DENIED_INVALID_PRINCIPAL` with `allow: false` (POL-04, Invariant 1). | Unit test in `internal/policy/engine_test.go` evaluating empty and anonymous principal inputs. |
| **Tampering (T)** | Discrepancy between Go request representation and Rego policy schema fields leads to unmapped attributes or silent evaluation corruption. | Strongly typed Go input structs in `internal/policy/types.go` strictly mirror `policies/schemas/input.schema.json` and `output.schema.json` with exact JSON tag names and types. | Unit tests in `internal/policy/engine_test.go` validating schema serialization against JSON schemas. |
| **Repudiation (R)** | Authorization decisions are non-deterministic or lack explainability, preventing auditing of denial causes. | Policy Decision Point yields structured `Decision` object containing explicit boolean `allow`, exact string `reason_code`, and monotonic `snapshot_version` (POL-02). | Assertions in `tests/security/rbac_matrix_test.go` verifying discrete reason codes across all permission evaluations. |
| **Information Disclosure (I)** | Rego evaluation failures or runtime errors leak internal rule ASTs or system environment. | `Evaluate()` fails closed on any query evaluation error, returning sanitized `Decision{Allow: false, ReasonCode: "EVALUATION_ERROR"}` with zero internal leakage. | Negative unit test in `internal/policy/engine_test.go` injecting malformed input and checking decision structure. |
| **Denial of Service (D)** | Parsing and compiling Rego AST on every incoming HTTP request causes 100% CPU utilization and 300ms latency spikes on the hot path. | Policy module is compiled once at startup/snapshot load via `rego.PrepareForEval(ctx)`. Precompiled query executes thread-safely in-memory in ~0.15ms (<2ms SLA) with zero network calls (POL-01, ADR-0002). | Benchmark `BenchmarkOPAEval` in `internal/policy/engine_test.go` asserting <0.2ms latency budget and zero network I/O. |
| **Elevation of Privilege (E)** | User with `developer` role accesses administrative endpoints (`/api/admin/users`); unmapped route defaults to allow. | Rego enforces `default allow := false` and `default reason_code := "DENIED_DEFAULT"`. Explicit negative rule denies developer role access to admin service with `DENIED_DEVELOPER_ADMIN_FORBIDDEN` (POL-02, POL-03, Invariant 1). | Comprehensive RBAC test suite in `tests/security/rbac_matrix_test.go` verifying role and workload boundary enforcement. |
</threat_model>

## Executive Summary

Plan 01-02 establishes the Policy Decision Point (PDP) for Aegis: the embedded, in-memory Open Policy Agent (OPA) engine. It maps Phase 0 JSON schemas to strongly typed Go domain structs (`internal/policy/types.go`), provides a static snapshot loader for local policy files (`internal/policy/loader.go`), compiles the Rego v1 policy once at startup using `rego.PrepareForEval(ctx)` (`internal/policy/engine.go`), and enforces strict default-deny authorization with discrete reason codes. The implementation is verified by microsecond latency benchmarks (<0.2ms per evaluation with zero network hops) and an automated RBAC security matrix test suite covering developer, finance, admin, and workload role permissions.

<acceptance_criteria>

- `NewEngine(ctx context.Context, regoCode string) (*Engine, error)` compiles the Rego module into a prepared query targeting `data.aegis.authz.decision` using `rego.PrepareForEval(ctx)`.
- `Evaluate(ctx context.Context, input PolicyInput) (Decision, error)` evaluates `input` purely in-memory using `preparedQuery.Eval(ctx, rego.EvalInput(input))`.

  - Evaluation error returns `Decision{Allow: false, ReasonCode: "EVALUATION_ERROR", SnapshotVersion: input.SnapshotVersion}` and error.

  - Malformed decision value returns `Decision{Allow: false, ReasonCode: "MALFORMED_DECISION", SnapshotVersion: input.SnapshotVersion}`.

  - `TestDefaultDeny`: asserts unmapped routes return `Allow: false` and `ReasonCode: "DENIED_DEFAULT"`.

  - `BenchmarkOPAEval`: executes repeated evaluations under benchmark harness asserting sub-0.2ms (<200µs) latency per evaluation with zero network calls.
- Test and benchmark commands exit with code 0:
  `go test -v -race ./internal/policy/ -run "TestDefaultDeny|TestFailClosed" && go test -bench=BenchmarkOPAEval -benchtime=1000x -benchmem ./internal/policy/`
</acceptance_criteria>

## Must-Haves
### Truths
- OPA queries are precompiled once at startup via `rego.PrepareForEval(ctx)`; hot-path policy evaluations execute purely in-memory in <0.2ms with zero network calls.
- Unmapped routes, evaluation errors, and missing principals fail closed returning `allow: false` and explicit reason codes (`DENIED_DEFAULT`, `DENIED_INVALID_PRINCIPAL`).
- Users with `developer` role can read orders and payments, but are rejected from administrative endpoints with `DENIED_DEVELOPER_ADMIN_FORBIDDEN`.
- Users with `finance` role can read and create payments, but cannot read orders or access admin endpoints.
- Users with `application-admin` role can manage admin users.
