# Plan 00-03: Rego Typed Input Schemas, Route Definitions & Seed Permission Matrix

<threat_model>
### Plan 00-03 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 00-03 Policies | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Ingress caller provides unauthenticated or malformed identity claims directly into policy input. | `policies/schemas/input.schema.json` strictly validates principal structure (`id`, `kind`: user\|workload\|anonymous, `roles`), rejecting arbitrary fields (`additionalProperties: false`). | Schema validation and OPA test suite testing anonymous/missing principal denial. |
| **Tampering (T)** | Attacker sends unexpected HTTP methods or uncanonical paths hoping to bypass route matching. | `input.schema.json` restricts HTTP methods to valid standard verbs and path to canonical pattern `^/api/.*$`. Rego matches canonical route attributes. | OPA unit tests checking path and method boundaries. |
| **Repudiation (R)** | Authorization engine yields boolean decisions without traceable explanation, preventing audit analysis. | `authz.rego` guarantees a discrete `reason_code` for every decision (`ALLOWED_DEVELOPER_ORDERS`, `DENIED_DEVELOPER_ADMIN_FORBIDDEN`, `DENIED_DEFAULT`). | Unit tests assert both `allow` boolean and exact `reason_code` values. |
| **Information Disclosure (I)** | Decision output leaks sensitive internal role mappings or policy rule internals to caller. | `output.schema.json` bounds decision object to `{allow, reason_code, snapshot_version}`, preventing policy AST leaks. | OPA decision structure contract validation. |
| **Denial of Service (D)** | Complex Rego rules perform unbounded set iteration or regex backtracking, exceeding 2ms evaluation SLA. | Rego v1 rules use deterministic constant-time set containment (`in`) and direct string equality checks without unbounded loops. | OPA evaluation benchmarks asserting sub-millisecond execution. |
| **Elevation of Privilege (E)** | Unmapped route or unspecified role defaults to permit; global admin wildcard `*:*` grant exists. | Invariant 1 enforcement: strict `default allow := false` and `default reason_code := "DENIED_DEFAULT"`. No global admin `*:*` grant is seeded. | OPA test suite proving unmapped route and role boundaries fail closed. |
</threat_model>

## Executive Summary

Plan 00-03 establishes the declarative policy engine foundation for Aegis. It defines strict JSON schemas (`policies/schemas/input.schema.json` and `output.schema.json`) constraining the in-memory OPA request context to typed, bounded fields. It defines canonical seed data catalogs (`policies/data/routes.json` and `seed_roles.json`) for the three private backend services (`orders`, `payments`, `admin`). It authors the production Rego v1 authorization policy (`policies/rego/authz.rego`) implementing strict default-deny and the complete seed permission matrix across developer, finance, application-admin, and workload identities. Finally, it provides a comprehensive unit test suite (`policies/tests/authz_test.rego`) proving 100% test coverage with zero failures.
