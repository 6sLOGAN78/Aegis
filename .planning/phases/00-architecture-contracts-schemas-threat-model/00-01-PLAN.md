# Plan 00-01: Architecture Decision Records (ADRs) & Zero-Trust Threat Model

<threat_model>
### Plan 00-01 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 00-01 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Ingress caller supplies spoofed `X-Aegis-*` or `Forwarded` headers; workload masquerades as gateway identity. | ADR-0001 mandates unconditional header stripping in `Rewrite` hook. ADR-0003 and Threat Model enforce dedicated mTLS listeners and backend assertion verification (`X-Aegis-Assertion`, `iss: aegis-gateway`). | Threat model maps Invariant 2, 5, 8 to negative integration tests. |
| **Tampering (T)** | Path traversal (`..`, `%2f`, `%00`) bypasses route matching; stale configuration snapshot replayed. | ADR-0001 defines strict zero-repair path rejection (HTTP 400). ADR-0004 specifies Ed25519-signed snapshots with strictly monotonic version numbers. | Threat model maps Invariant 7 and 9 to path fuzzing and snapshot verification tests. |
| **Repudiation (R)** | Mutating transaction (`POST /api/payments`) succeeds on backend but gateway crashes before logging decision. | ADR-0006 establishes mandatory pre-forward local disk Write-Ahead Log (WAL) append with `fsync()` before upstream network dispatch. | Threat model maps Invariant 10 to crash-recovery tests during database outage. |
| **Information Disclosure (I)** | Observability metrics expose sensitive principal tokens or PII; error responses leak internal stack traces. | Threat Model and ADR-0001 dictate bounded RFC 7807 error responses and Prometheus metric labels stripped of high-cardinality PII. | Threat model maps Invariant 11 to metric label schema inspection. |
| **Denial of Service (D)** | Redis dependency failure or disk WAL saturation causes unbounded gateway stall or silent failure. | ADR-0005 enforces 200ms Redis timeout with fail-closed HTTP 503 response. ADR-0006 defines 90% WAL saturation safety gate halting admissions. | Threat model maps failure semantics table to automated chaos injection tests. |
| **Elevation of Privilege (E)** | Partitioned gateway replica authorizations execute indefinitely against stale policy during control-plane partition. | ADR-0004 mandates 10-second signed freshness leases; replica drops readiness and returns HTTP 503 on protected routes after 60 seconds without renewal. | Threat model maps Invariant 4 and 9 to network partition tests. |
</threat_model>

## Executive Summary

Plan 00-01 produces the authoritative governance foundation for Aegis: six Architectural Decision Records (ADRs 0001 through 0006) in standard MADR format, and the comprehensive Zero-Trust Threat Model document. These artifacts codify non-negotiable architectural directions—including Go reverse proxying with modern `Rewrite` hooks, in-memory embedded OPA policy evaluation (<2ms SLA), physical dual-listener identity separation, monotonic Ed25519 signed snapshot streaming with 10s freshness leases, Redis fail-closed semantics (HTTP 503 on outage), and pre-forward disk WAL audit spooling with `fsync()`. The threat model defines system context, 7 trust boundaries, 4 attacker profiles, STRIDE taxonomy, and explicit verification mappings for all 12 non-negotiable security invariants from `spec.md` §3.

Create directory `docs/adr/` and author the 6 ADR files following MADR structure:

1. `docs/adr/0001-reverse-proxy-architecture.md`:
   - Title: "ADR-0001: Go Standard Library Reverse Proxy with Strict Path Validation and Rewrite Hook"
   - Context: Gateway must terminate ingress traffic, sanitize headers, validate paths without auto-repair, evaluate policies, and dispatch to private backends over mTLS.
   - Decision Drivers: Security boundary integrity (CWE-22, CWE-444), performance (<20ms added p99 latency), maintenance simplicity, zero third-party proxy runtime overhead.
   - Options Considered:
     - Option A: Standard Go `httputil.ReverseProxy` with modern `Rewrite` hook (*Chosen*)
     - Option B: Envoy Proxy with custom filter extensions / ext_authz
     - Option C: Deprecated `httputil.ReverseProxy.Director` hook
   - Decision Outcome: Choose Option A. The `Rewrite` hook decouples inbound `r.In` from outbound `r.Out`, prevents hop-by-hop leaks, and strips `X-Aegis-*` headers. Strict path validation rejects traversal (`..`), encoded slashes (`%2f`), duplicate slashes (`//`), and NUL bytes (`%00`) with HTTP 400 Bad Request immediately without path repair.
   - Invariant Mapping: Invariant 6 (Route identifies upstream), Invariant 7 (Identical validated path/method), Invariant 8 (No header impersonation).

2. `docs/adr/0002-in-memory-opa-embedding.md`:
   - Title: "ADR-0002: Embedded In-Memory OPA Engine on Request Hot Path"
   - Context: Gateway authorization requires microsecond-latency evaluation of declarative policies without introducing external daemon network hops or split-brain failure states.
   - Decision Drivers: Latency SLA (<2ms p99 evaluation budget), zero network dependency on hot path, deterministic failure handling, memory safety.
   - Options Considered:
     - Option A: Embedded OPA SDK in Go (`github.com/open-policy-agent/opa/v1/rego`) with precompiled queries (*Chosen*)
     - Option B: External OPA HTTP Daemon (`http://opa:8181/v1/data`)
     - Option C: Hand-rolled custom Go RBAC engine
   - Decision Outcome: Choose Option A. Precompiled queries (`rego.PrepareForEval`) execute in-memory in <0.2ms. Policies evaluate against immutable snapshot references swapped atomically via `sync/atomic.Pointer`.
   - Invariant Mapping: Invariant 1 (Default deny), Invariant 7 (Policy and proxy share identical snapshot version).

3. `docs/adr/0003-dual-listener-identity-separation.md`:
   - Title: "ADR-0003: Physical Dual-Listener Identity Separation & Backend Assertions"
   - Context: Gateways serve both human browser/API callers (bearing JWTs) and automated service-to-service workloads (bearing client certificates). Multiplexing credentials on a single listener creates confused-deputy vulnerabilities and ambiguous principal resolution.
   - Decision Drivers: Principal clarity (NIST SP 800-207), direct bypass elimination, cryptographic binding.
   - Options Considered:
     - Option A: Physical dual listeners (`:8080`/`:8443` for User JWT vs `:9443` for Workload mTLS) with signed backend assertions (*Chosen*)
     - Option B: Single multiplexed port accepting both client certificates and bearer JWTs
     - Option C: Trusting load-balancer forwarded client certificate headers (`X-Forwarded-Client-Cert`)
   - Decision Outcome: Choose Option A. User listener rejects workload certs; Workload listener rejects bearer tokens. Gateway mints short-lived (<=15s) Ed25519 assertion JWT (`X-Aegis-Assertion`) on proxy dispatch. Backends enforce mTLS verifying gateway cert and assertion claims.
   - Invariant Mapping: Invariant 2 (Identity from verified JWT or client cert only), Invariant 3 (Workload cert authenticates, policy authorizes), Invariant 5 (Backends accept only gateway client identity + assertion), Invariant 12 (Network location is never authorization).

4. `docs/adr/0004-signed-freshness-leases-and-snapshots.md`:
   - Title: "ADR-0004: Monotonic Signed Snapshots with 10-Second Freshness Leases"
   - Context: Dynamic routing and policy updates must propagate across distributed gateway replicas without split-brain, rollback attacks, or indefinite operation on stale configuration.
   - Decision Drivers: Strong consistency bounds, partition resilience, cryptographic integrity.
   - Options Considered:
     - Option A: Bidirectional gRPC streaming with Ed25519 monotonic snapshots and 10s freshness leases (*Chosen*)
     - Option B: Polling relational database (PostgreSQL) directly from gateway replicas
     - Option C: Indefinite caching of last valid policy during control-plane partition (fail-open)
   - Decision Outcome: Choose Option A. Snapshots are signed with Ed25519 and contain monotonic integer versions. Control plane streams 10-second freshness leases. If control plane is unreachable for >60 seconds, gateway drops readiness and fails closed returning HTTP 503 on protected routes.
   - Invariant Mapping: Invariant 4 (TLS verification enabled), Invariant 9 (Atomic snapshot activation with monotonic versioning).

5. `docs/adr/0005-redis-fail-closed-semantics.md`:
   - Title: "ADR-0005: Redis Atomic Token Bucket Rate Limiting and Fail-Closed Revocation Semantics"
   - Context: Instant revocation of compromised tokens (`jti`) and emergency principal quarantine (<5s propagation) requires distributed shared state across replicas.
   - Decision Drivers: Containment speed (<5 seconds), zero-trust fail-closed guarantee, bounded latency (200ms deadline).
   - Options Considered:
     - Option A: Redis token-bucket and revocation lookup with 200ms deadline and fail-closed HTTP 503 on failure (*Chosen*)
     - Option B: Fail-open fallback (allow requests if Redis is unreachable)
     - Option C: Synchronous PostgreSQL queries for quarantine on every request
   - Decision Outcome: Choose Option A. Redis is an explicit availability dependency. If Redis times out (>200ms) or is unreachable, protected requests fail closed with HTTP 503 Service Unavailable. No permissive fallback is permitted.
   - Invariant Mapping: Invariant 1 (Default deny & fail closed).

6. `docs/adr/0006-pre-forward-wal-audit-spool.md`:
   - Title: "ADR-0006: Pre-Forward Append-Only Disk WAL Spool with Asynchronous Database Worker"
   - Context: Audit logging of permitted requests must be durable before upstream execution to prevent repudiation, while shielding request latency from database stalls.
   - Decision Drivers: Durability before effect (Invariant 10), gateway latency (<20ms p99), database decoupling.
   - Options Considered:
     - Option A: Local append-only disk Write-Ahead Log (WAL) with `fsync()` before forwarding, drained by async Go worker (*Chosen*)
     - Option B: Synchronous PostgreSQL insert before proxying
     - Option C: In-memory buffered channel directly to database worker
     - Option D: External message broker (Kafka/RabbitMQ)
   - Decision Outcome: Choose Option A. Gateway writes and `fsync`s decision record to local disk WAL before forwarding. Async worker delivers batches to PostgreSQL with at-least-once delivery and deduplication. If spool disk reaches 90% capacity, admission halts with HTTP 503.
   - Invariant Mapping: Invariant 10 (Permitted requests require pre-forward durable audit record), Invariant 11 (Management access separately authorized).
