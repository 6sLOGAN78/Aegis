# Plan 04-01: Control Plane REST Management APIs (/control/v1) with RBAC, CSRF Protection, and Optimistic Concurrency

<threat_model>
### Plan 04-01 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 04-01 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Data-plane bearer token or forged operator token presented to administrative `/control/v1` endpoints. | Management endpoints require an authenticated operator session cookie (`aegis_session`) issued by `SessionManager`. Invariant 11 strictly isolates control plane authentication: data-plane credentials presented to `/control/v1` return `HTTP 403 Forbidden` (`DATA_PLANE_CREDENTIALS_REJECTED`). | Unit tests in `internal/control/api_test.go` asserting data-plane tokens are rejected on all `/control/v1` routes with HTTP 403. |
| **Tampering (T)** | Concurrent operators clobbering route definitions or policy drafts (lost-update anomaly). | Mutating operations (`/publish`, `/rollback`, route modifications) enforce RFC 7232 optimistic concurrency via `ETag` and `If-Match` headers. If `If-Match` does not match the active snapshot version or resource hash, the request is rejected with `HTTP 412 Precondition Failed` without applying mutations. | Unit tests in `internal/control/concurrency_test.go` validating ETag generation and 412 Precondition Failed on mismatch. |
| **Tampering (T)** | Malicious third-party web application issues Cross-Site Request Forgery (CSRF) mutations via operator's ambient browser cookies. | Session cookies enforce `HttpOnly; SameSite=Strict; Secure`. Mutating operations (`POST`, `PUT`, `DELETE`, `PATCH`) require a cryptographically random token in the `X-CSRF-Token` header matching the active session CSRF secret. Missing or mismatched tokens fail closed with `HTTP 403 Forbidden` (`CSRF_TOKEN_INVALID`). | Unit tests in `internal/control/session_test.go` verifying that mutating requests without `X-CSRF-Token` fail with 403, while safe methods (`GET`) succeed. |
| **Repudiation (R)** | Operator performs emergency principal quarantine, token revocation, or policy rollback without audit attribution. | Session context extracts the authenticated operator username (`actor`) and injects it into all snapshot envelopes, database audit logs, and Redis quarantine records. | Unit tests in `internal/control/api_test.go` verifying operator identity attribution in publish, rollback, and quarantine endpoints. |
| **Information Disclosure (I)** | Unhandled panics or raw database errors leaking internal SQL schema structure, file paths, or credentials in error responses. | Chi `middleware.Recoverer` catches unhandled panics; all API error responses conform to `controlv1.ErrorResponse` RFC 7807 problem details with sanitized error codes, correlation `request_id`, and no raw stack traces. | Unit tests asserting error payloads return structured JSON with UUID `request_id` and no internal database connection strings. |
| **Denial of Service (D)** | Client network timeouts causing duplicate retries of snapshot publishing, leading to monotonic version inflation and duplicate gRPC broadcasts. | Mutating endpoints require `Idempotency-Key` headers (UUID). An in-flight check locks concurrent duplicate executions returning `HTTP 409 Conflict`. Completed responses are cached for 24 hours, replaying the original status and payload with `Idempotent-Replay: true`. | Unit tests in `internal/control/concurrency_test.go` verifying 409 Conflict on concurrent requests and cached replay on subsequent calls. |
| **Elevation of Privilege (E)** | Operator with `viewer` or `auditor` role attempting to publish policies, execute rollbacks, or quarantine principals. | Granular RBAC middleware (`RBACMiddleware`) checks session roles: `sec-ops` (full mutation and emergency quarantine), `auditor` (read-only audit events and topology), `viewer` (read-only routes and drafts). Unauthorized roles are rejected with `HTTP 403 Forbidden`. | Unit tests in `internal/control/session_test.go` asserting `viewer` and `auditor` cannot invoke mutating endpoints. |
</threat_model>

## Executive Summary

Plan 04-01 delivers the authoritative control plane REST management API (`/control/v1`) running on dedicated port `:8084` using `github.com/go-chi/chi/v5`. In accordance with OPS-01, OPS-02, OPS-04, and Invariant 11, the control plane is strictly decoupled from the data plane, providing secure policy administration, live Rego dry-run simulation, monotonic snapshot publishing and rollbacks, emergency quarantine, and indexed audit inspection.

This plan builds the session security engine (`SessionManager` with `HttpOnly; SameSite=Strict` cookies and `X-CSRF-Token` validation), optimistic concurrency controls (`ETag` and `If-Match` returning `412 Precondition Failed`), idempotency deduplication (`IdempotencyStore` with in-flight `409 Conflict` locking and 24-hour response caching), RBAC role validation, PostgreSQL storage repositories for policy drafts (`PolicyRepo`) and partitioned audit logs (`AuditRepo`), and the complete Chi router mounting all `/control/v1` routes matching `api/openapi/control-v1.yaml` and `pkg/api/control/v1/types.gen.go`.

## Must Haves

### Truths
- An operator authenticating via `POST /control/v1/auth/login` receives an `HttpOnly; SameSite=Strict; Secure` session cookie and a 256-bit CSRF token.
- Mutating management requests (`POST`, `PUT`, `DELETE`, `PATCH`) lacking or presenting an invalid `X-CSRF-Token` header are rejected immediately with `HTTP 403 Forbidden` (`CSRF_TOKEN_INVALID`).
- Presenting data-plane credentials or user JWT tokens to `/control/v1` returns `HTTP 403 Forbidden` (`DATA_PLANE_CREDENTIALS_REJECTED`), satisfying Invariant 11.
- Publishing or rolling back a policy without a valid `If-Match` header matching the active version is rejected with `HTTP 412 Precondition Failed` without applying changes.
- Duplicate mutating requests with the same `Idempotency-Key` return `HTTP 409 Conflict` during execution and return the cached response with `Idempotent-Replay: true` after completion.
- Candidate Rego simulation compiles in-memory and returns Allow/Deny decisions, reason codes, and microsecond latencies (<2ms) without touching production traffic.
- Monotonic rollbacks republish historical snapshot configuration under version $N+1$, ensuring forward monotonicity across all gateway replicas.
- Principal quarantines and token revocations write directly to Redis with <5s propagation.
