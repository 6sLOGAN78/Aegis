# Plan 04-03: Real-Time Replica Convergence Tracking, Emergency Quarantine UI, and Prometheus Telemetry Metrics

<threat_model>
### Plan 04-03 STRIDE Threat Analysis

| Threat Category | Specific Threat Scenario | Mitigation in Plan 04-03 Architecture | Verification Mechanism |
|---|---|---|---|
| **Spoofing (S)** | Malicious external actor scrapes internal telemetry or injects spoofed replica convergence status. | Prometheus metrics listeners are bound exclusively to dedicated private internal ports (`:9091` on gateway, `:9092` on control plane) completely separate from public ingress; replica convergence status is compiled exclusively from authenticated gRPC bidirectional stream connections and signed `SnapshotAck` messages. | Unit and integration tests verifying private listener port binding and rejection of unauthorized convergence reports. |
| **Tampering (T)** | Metric label cardinality explosion (poisoning) exhausts memory and causes Prometheus TSDB crash (e.g. injecting user IDs or IPs into labels). | Metric labels are strictly bounded to static, predefined enum sets (`method`, `route_id`, `status`, `decision`, `reason_code`). High-cardinality attributes—including user IDs, client IPs, raw URLs, and query parameters—are strictly forbidden from Prometheus collectors and remain exclusively in append-only audit logs. | Unit tests in `internal/telemetry/metrics_test.go` scraping `/metrics` and asserting zero high-cardinality label keys. |
| **Repudiation (R)** | Operator triggers emergency principal quarantine or token revocation without confirmation or justification. | `EmergencyQuarantine.tsx` enforces a destructive confirmation modal requiring operators to explicitly type "QUARANTINE" or "REVOKE" along with a mandatory audit reason. The authenticated operator ID (`actor`) is recorded in both Redis and PostgreSQL. | UI and API unit tests verifying quarantine requests without typed confirmation and reason are rejected. |
| **Information Disclosure (I)** | Operational metrics endpoint leaks sensitive user PII, bearer tokens, or proprietary customer route patterns. | Telemetry middleware normalizes dynamic URL paths into canonical route IDs (`route.RouteID`) before incrementing metrics counters, preventing sensitive path parameters from appearing in metric labels. | Unit tests asserting sanitized route IDs in Prometheus metric outputs. |
| **Denial of Service (D)** | High-frequency polling of `/control/v1/gateways` overloads control plane database during operational incident. | `gateway_handler.go` caches live in-memory gRPC client streams from `distServer` and queries indexed database acknowledgments with low overhead; frontend dashboard polls at a bounded 5-second interval. | Load assertion during integration test verifying negligible CPU overhead under polling. |
| **Elevation of Privilege (E)** | Non-privileged operator triggering cluster-wide quarantine or token revocation from dashboard. | Emergency quarantine endpoints are guarded by `RBACMiddleware(role: "sec-ops")` and CSRF token validation; unauthorized roles return `HTTP 403 Forbidden`. | Unit tests verifying `viewer` and `auditor` roles cannot invoke quarantine mutations. |
</threat_model>

## Executive Summary

Plan 04-03 completes the operational observability and fleet governance capabilities of Aegis. In accordance with OPS-01, OPS-03, and DIST-02, operators require real-time visibility into distributed gateway replica convergence, rapid sub-5-second emergency quarantine interventions, and comprehensive Prometheus telemetry without cardinality poisoning.

This plan implements the replica convergence aggregation endpoint (`/control/v1/gateways`), builds the real-time Cluster Topology dashboard grid with lease renewal countdown bars, delivers the Emergency Quarantine modal with destructive confirmation safety gates, establishes the low-cardinality Prometheus telemetry registry and HTTP metrics middleware on private listeners (`:9091` / `:9092`), integrates the control plane and gateway daemons with graceful multi-listener lifecycle management, and provides an end-to-end integration test suite validating the entire operational workflow.

- `internal/control/gateway_handler.go` implements `HandleListGateways(w http.ResponseWriter, r *http.Request)`:
  - Fetches replica acknowledgment records from `snapshotRepo.ListGatewayAcks(ctx)` and in-memory active replica statuses from `ackTracker.GetReplicaStatuses()`.
  - Determines health status for each gateway:
    - `healthy`: Active version equals active control plane snapshot version and lease expiration is in the future.
    - `degraded`: Gateway is connected and heartbeating but active version lags behind active control plane snapshot version.
    - `partitioned`: Gateway heartbeat is older than 60 seconds (exceeds fail-closed boundary) or status is `ACK_STATUS_REJECTED`.

  - Endpoint accessible to `sec-ops`, `auditor`, and `viewer` roles.
