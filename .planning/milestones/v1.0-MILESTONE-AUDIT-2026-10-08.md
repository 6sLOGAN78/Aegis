## Re-run 2026-10-08 (after Phase 7 was added)

The audit command was run again after Phase 7 was added to the roadmap. No file outside `.planning/` has changed since this report was written, so the integration check was not repeated and every finding below stands as written.

What changed in scope:

- **Phase 7** — "Close gaps B1, B3, B4: align compose configs with current binaries (REV-03, AUD-03)" — now belongs to v1.0. It has no plans, no SUMMARY and no VERIFICATION.md, so it counts as an unverified phase (7/8).
- Phase 7 targets closure group 1 below. It names B1, B3 and B4; it does not cover the rest of what keeps REV-03 and AUD-03 unsatisfied (no `jti` from the issuer, percent-encoded SPIFFE quarantine keys, B7, B8).
- B2, B5, B6, B7 and B8 have no closure phase yet.
- `REQUIREMENTS.md` now shows the 14 partial/unsatisfied requirements unchecked and marked "Gap closure" in the traceability table, still mapped to their original phases.

## Why this differs from the previous audit

On paper nothing changed: all seven `VERIFICATION.md` files are `passed`, every one of the 38 requirement IDs appears in a phase verification, in a SUMMARY `requirements-completed` list, and is checked `[x]` in the archived requirements. By the 3-source matrix alone the score is 38/38.

The difference is the integration check. This time it traced each requirement into the production binaries (`cmd/gateway`, `cmd/control-plane`, `cmd/audit-worker`, backends) and deployment configs instead of accepting per-package tests as evidence. Components are implemented and unit-tested; a substantial share are not connected to each other or to the shipped configs.

## What holds

The gateway request pipeline is genuinely wired end to end in `cmd/gateway/main.go`, with no step behind a permissive default:

concurrency limiter → request ID + size limits → lease check → snapshot-present check → path validation → authn (JWT / mTLS SPIFFE) → revocation (200ms, fail closed) → route match → rate limit → OPA → pre-forward WAL fsync + 90% gate → assertion mint → mTLS forward.

Routes and policy at request time come from the atomically swapped snapshot, not static startup files. The core value — default-deny, fail-closed — is intact in code. `go build`, `go vet` exit 0; `go test -count=1 ./...` reports 26 packages ok, 170 top-level tests pass, 0 fail, 0 skip.
